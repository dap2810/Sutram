baseconv

layer: alloc Convert between base-10 bigint digit arrays and digit-value arrays in base 2, 8, 10, 16. The intermediate is a pankti of integer digit values (0..15), most significant first — not a byte string, to avoid packing issues. chandas

layer: core After Pingala's Chandahśāstra (~2nd c. BCE). Sanskrit metre is built from two syllable weights — laghu (light) and guru (heavy) — so an n-syllable metre is a sequence of two choices: there are exactly 2^n of them. Pingala gave the doubling rule for 2^n, the Meru-prastāra (Pascal's triangle) to count how many metres have exactly k guru syllables, and the mātrā-meru, which generates the Fibonacci numbers. A pattern is carried as an integer bitmask: bit i (LSB = first syllable) is 1 for guru, 0 for laghu. The integer value IS the pattern's index in the prastāra.

fmt

layer: alloc Number and string formatting on BYTE strings (packed bytes, explicit lengths, `strb` idiom): every function writes packed bytes into `out` with a 0 terminator and returns the byte count. This is the modern idiom; the older `lib/strconv.smlib` works on CELL arrays (pankti of char codes) and has no width/alignment/grouping/fixed-decimal/sign surface — fmt is the formatting module, strconv is the conversion module. Do not mix the representations: fmt outputs are bytes (read with char_at), strconv outputs are cells (read with [i]). Defaults, stated once here and at each function: - Bases: no prefix unless the _pre / flags form is used. - Grouping: fmt_group defaults to INDIAN grouping (12,34,567). - Rounding: fmt_fixed rounds HALF AWAY FROM ZERO (2.5 -> 3, -2.5 -> -3). - Centre padding: the extra pad byte goes RIGHT. - INT64_MIN (-2^63) is handled: |MIN| = 2^63 does not fit in int64, so the digit writers split it (hi/lo) instead of negating it. Every int64 value works. - fmt_fixed is exact while |x| * 10^places < 2^52; beyond that the +0.5 rounding step is below float precision. |x| * 10^places must fit in int64. places is clamped to 0..9. All signatures stay within the 6-argument cap. --- integer digits (private helper) --- fmt_digits(v, out) — write the decimal digits of |v| (no sign) into out as packed bytes. Returns the digit count. Internal; the public formatters below build on it.

ganita

layer: core After Aryabhata's Kuttaka (~499 CE) and the Chakravala of Jayadeva and Bhaskara II (~1150 CE). KUTTAKA ("the pulveriser") solves the linear indeterminate equation ax + by = c. It is the ancestor of the extended Euclidean algorithm. CHAKRAVALA ("the wheel") solves x^2 - N*y^2 = 1 (Pell's equation); N = 61 gives x = 1766319049, y = 226153980. CHECKED / SATURATING ARITHMETIC (R18) lives here too: ganita is the arithmetic module. See the notes above ganita_checked_add. kuttaka(a, b, c) -> x such that a*x is congruent to c (mod b). Requires gcd(a, b) to divide c. Returns x (a particular solution).

kalana

layer: core Built on typed `kosh dasham` parameters (T18) and the float fast paths (F1/F2/FG1/FC1). Every function READS its kosh parameters only — never `kosh_push` on a parameter, which the compiler deliberately rejects because the pointer is passed by value. Sutram has no first-class functions, so anything that would take a callback instead takes either SAMPLES (for integration/differentiation) or POLYNOMIAL COEFFICIENTS (for root finding). Coefficients are in ascending order: c[0] + c[1]*x + c[2]*x^2 + ... --------------------------------------------------------------- Integration over sampled data --------------------------------------------------------------- Trapezoidal rule. xs and ys are sample points and values; uses the shorter length.

list

layer: alloc Representation decision — QWORD CELLS (the pankti/kosh convention), not byte strings. Reasoning: - A list is the growable analogue of pankti: same element model (one qword per element), same indexing, same literal passing (list_push(l, 42)). A byte-string list would be a string-list only, and would force every element through copy + length bookkeeping. Users with byte strings can store POINTERS (list_push(l, ptr)) — a qword list of pointers is the escape hatch, and it is the caller's job to keep the pointed-to buffers alive. - No mixing: every element in this module is a qword. Do not pass byte-string buffers here expecting string semantics, and do not pass fmt/strb outputs as elements. - dasham elements are NOT supported. An untyped parameter truncates a dasham argument to its integer part (the R15 trap), so list_push(l, 3.7) stores 3. There is no way to store a dasham bit pattern through this API. Format floats first (fmt) if you need them as text, or keep a parallel structure. Two handle layouts (do NOT mix families on one handle): - list / stack handle: header [len, cap, data_ptr]; data is a separate cell array. The HANDLE address is stable across growth — only the data pointer inside it moves. - queue handle: header [len, cap, data_ptr, head]; a RING BUFFER (see queue_enqueue). queue_* on a list handle (or list_* on a queue handle) reads the wrong header and corrupts memory. Growth rule: when len == cap, capacity DOUBLES (cap *= 2), a new data array is allocated, elements are copied in logical order, and the header's data pointer is updated. The old data array is NOT freed — the language has no deallocation primitive, so growth leaks the previous array (same as every other growing structure in the stdlib). Capacity never shrinks: list_clear and queue dequeue keep the allocated capacity. Allocation failure: if nirmmita returns 0 during growth, the operation returns 0 (or ok[0] = 0) and the structure is UNCHANGED. list_init returns 0 if either allocation fails. Out-of-bounds reads: list_get returns 0 for i outside [0, len). 0 is a legal stored value, so check list_len first when it matters. list_set / list_insert_at / list_remove_at return 1 ok / 0 out of bounds (or allocation failure for insert). stack_pop / stack_peek / queue_dequeue / queue_peek return the value and set ok[0] (a 1-cell pankti) to 1 on success, 0 when empty — the value alone cannot signal emptiness. All signatures stay within the 6-argument cap.

map

layer: alloc Open addressing with linear probing over parallel pankti arrays. KEY REPRESENTATION: byte strings (the R10 strb_* surface), NOT char-code arrays. Rationale: keys are usually literals ("apple"), and byte strings let the caller pass a literal directly — no hand-built cell array. The hash (lib/hash.smlib fnv1a, via `ayojan hash` below) is byte-based (char_at), so the choice is consistent end to end. Worked example: ayojan map mukhya() { vitti m = map_init(8) map_put(m, 8, "apple", 5, 42) likha(map_get(m, 8, "apple", 5)) # 42 likha("\n") } This matches lib/string.smlib's header: a byte string is bytes packed 1-per-byte (a literal, or a set_char-built buffer), measured with an explicit length, read with char_at. Do not pass char-code arrays here. Layout of the map buffer m (qword cells, except the key bytes): m[0] capacity m[1] live entry count m[2+i] state[i] (0 = empty, 1 = live), i in 0..cap-1 m[2+cap+i] keylen[i] m[2+2*cap+i] val[i] key bytes: byte region at byte offset (2+3*cap)*8, KEY_MAX bytes/slot. KEY_MAX = 32: keys longer than 32 bytes are truncated to 32, consistently on put/get/contains/remove (documented; excluded from the properties). cap must be >= 1 (clamped). Probing wraps modulo cap. DELETION is backward-shift (Knuth 6.4R): the freed slot is filled by shifting later probe-chain entries back toward their home bucket, so there is no "deleted" state and no tombstones — a lookup stops at the first empty slot and never misses a live entry. ABSENT SENTINEL: map_get returns -1 (0-1) for a missing key. Values are programmer-managed integers; do not store -1 as a value unless you disambiguate with map_contains first. FULL TABLE: map_put returns 0 and changes nothing.

strb

layer: core The string toolkit operating on BYTE-PACKED strings — the representation of a literal and of set_char-built buffers. This is the ROUND-10 answer to the R9 gap: a programmer holding "hello world" can now use the toolkit directly, with no hand-built char-code array. THE TWO REPRESENTATIONS, side by side (kept consistent with the char-code array (lib/string.smlib R9 toolkit): qword cells, one char code per cell, read with h[i] (8-byte stride). Idiom: vitti h = nirmmita(6*8); h[0]=104; h[1]=105 ("hi" as cells); str_find(h, 2, nd, 1). byte string (this module): bytes packed 1-per-byte, read with char_at(s, i) (1-byte stride), written with set_char(s, i, v), measured with vartani_len(s). Idiom: strb_find("hi", 2, "i", 1) -> 1; or vitti b = nirmmita(8); set_char(b,0,104); set_char(b,1,105); set_char(b,2,0); strb_len(b) -> 2. Do NOT mix them: h[i] on a byte string reads 8 bytes at once, and char_at on a char-code array reads one byte of a qword cell. This lives in its own module (not inside string.smlib) because the compiler has a fixed AST ceiling: inlining the combined module together with the other stdlib modules exceeded it (suite tests 87/99/102). The char-code toolkit in lib/string.smlib is byte-for-byte unchanged. Conventions: lengths are explicit (source of truth); out-buffers get a 0 terminator via set_char; the caller allocates generously. Empty needle matches at 0; "not found" is -1. All signatures stay within the compiler's 6-argument cap (repl is 0-terminated, its length derived). SLICE-BOUNDARY RULES (WS4, R23 audit): a slice is a (pointer, length) pair into a larger buffer, with NO terminator at the slice end. - Every strb_* function takes an explicit length and stops at it: strb_find_char("hello world", 5, 'w') is -1. The NUL-terminated forms (find_char, count_char, count_vowels, is_all_digits, str_equals) scan to the terminator, so they are WRONG on slices. Never pass a slice to them. - strb_len / str_len / vartani_len scan to the terminator: they cannot be used on slices at all. A slice carries its length. - strb_replace / str_replace's repl is 0-terminated (its length is derived), so repl cannot be a slice. To use a slice as repl, strb_dup it into a terminated buffer first. An explicit-length repl form would need 7 arguments, over the compiler's 6-argument cap, so the terminated form stays. - The (s, i) char predicates take no length: the caller must keep i in bounds; they read char_at(s, i) unconditionally. strb_split/strb_join use the same length-prefixed segment format as str_split/str_join (R9): [len0, b0, b1, ..., len1, b0, ...], one byte value per cell. strb_pack(cells, n, out) — pack a qword-cell sequence (one byte value per cell, the str_split/strb_split segment format) into contiguous bytes. string

layer: core Built on `vartani_len` and `char_at`, both verified to honour their arguments. R52 audit: `char_code(s, i)` already honours i in the compiler; a one-argument `char_code(s)` remains a compatible alias for the first byte. This library continues to call `char_at(s, i)` as before, without changing its API. ASCII only for the character predicates; multi-byte UTF-8 is not split. SLICE-BOUNDARY RULES (WS4, R23 audit): the older byte-string functions below (str_len, count_vowels, count_char, find_char, is_all_digits, str_equals) scan to the NUL terminator and are WRONG on slices — a slice has no terminator at its end. Use the explicit-length strb_* forms on slices. str_replace's repl is 0-terminated; see the strb.smlib header for why and for the strb_dup workaround. The (s, i) char predicates take no length: the caller keeps i in bounds.
