anukram

layer: core The library's one new capability area: encode values into a flat byte buffer and decode them back, with bounds checking. Format: i64 — 8 bytes, little-endian, two's complement bytes — 8-byte little-endian length (n) followed by n payload bytes Buffers are byte strings (char_at / set_char), caller-allocated and caller-sized. Every put/get takes (buf, pos, cap): pos is the cursor, cap is the buffer size in bytes. On success the function returns the new cursor; on overrun (or a corrupt negative length when decoding) it returns -1 and the destination buffer is untouched (out_n may hold the decoded length if the length itself was readable). The caller owns the buffer and must check for -1, exactly like checking ok. put_bytes requires src and dst NOT to overlap: it writes the length header before copying the payload, so an overlapping src would be clobbered mid-copy. get_bytes requires buf and dst not to overlap for the same reason. Deliberately not here: floats (the language has no bit-cast primitive to turn a dasham into bits), varints (fixed-width is enough for this first area), and schema/versioning (the caller owns the field order; there is no header). anukram_maap_ashtak(n) — encoded size of an n-byte payload: 8 + n.

chandas

layer: core After Pingala's Chandahśāstra (~2nd c. BCE). Sanskrit metre is built from two syllable weights — laghu (light) and guru (heavy) — so an n-syllable metre is a sequence of two choices: there are exactly 2^n of them. Pingala gave the doubling rule for 2^n, the Meru-prastāra (Pascal's triangle) to count how many metres have exactly k guru syllables, and the mātrā-meru, which generates the Fibonacci numbers. A pattern is carried as an integer bitmask: bit i (LSB = first syllable) is 1 for guru, 0 for laghu. The integer value IS the pattern's index in the prastāra.

khand

layer: core The string toolkit on BYTE-PACKED strings (the representation of a literal and of set_char-built buffers). Own module (not inside string.smlib) because the compiler has a fixed AST ceiling. THE TWO REPRESENTATIONS (see also lib/string.smlib): char-code array: qword cells, one char code per cell, h[i]. byte string: bytes packed 1-per-byte, char_at(s, i) / set_char(s, i, v) / vartani_len(s). Do NOT mix them: h[i] on a byte string reads 8 bytes at once; char_at on a char-code array reads one byte of a qword cell. Conventions: lengths are explicit; out-buffers get a 0 terminator; the caller allocates generously. Empty needle matches at 0; "not found" is -1. All signatures stay within the 6-argument cap. SLICE-BOUNDARY RULES (R23): a slice is (pointer, length) into a larger buffer, with NO terminator at the slice end. Every strb_* function takes an explicit length and stops at it. The NUL-terminated forms (anwesh_akshar, gan_akshar, gan_swar, asti_sarv_ank, varna_sam) scan to the terminator — WRONG on slices. khand_maap / varna_maap / vartani_len scan to the terminator and cannot be used on slices. khand_pratisthap's repl is 0-terminated (length derived), so repl cannot be a slice; khand_pratilip it into a terminated buffer first. khand_bhed/khand_yuj use the length-prefixed segment format of varna_bhed/varna_yuj (R9): [len0, b0, ..., len1, b0, ...]. khand_bandh(cells, n, out) — pack a qword-cell sequence (one byte value per cell, the varna_bhed/khand_bhed segment format) into contiguous bytes. madhava

layer: core After Madhava of Sangamagrama (~1340-1425 CE) and the Kerala school of astronomy and mathematics. Madhava gave infinite-series expansions for the sine, cosine and arctangent functions, and from the arctangent series a rapidly converging series for pi - more than two centuries before Newton, Gregory and Leibniz. These use T12 scalar floats (dasham). vargit root by Newton's method (Babylonian), to float precision. v <= 0 returns 0.0. 1000 iterations: Newton from g = v halves the guess until it reaches sqrt(v) (~512 halvings for v = 1.8e308); 40 iterations gave 1e288 for sqrt(1e300).

suchi

layer: alloc Elements are QWORD CELLS (the mala/kosh convention), not byte strings. Users with byte strings store POINTERS (suchi_khip(l, ptr)); the caller keeps the pointed-to buffers alive. No mixing: every element here is a qword. dasham elements are NOT supported — an untyped parameter truncates a dasham argument to its integer part. Two handle layouts (do NOT mix families on one handle): - list / stack handle: header [len, cap, data_ptr]; data is a separate cell array. The HANDLE address is stable across growth — only the data pointer inside it moves. - queue handle: header [len, cap, data_ptr, head]; a RING BUFFER (see avali_pravesh). queue_* on a list handle (or list_* on a queue handle) reads the wrong header and corrupts memory. Growth rule: when len == cap, capacity DOUBLES, a new data array is allocated, elements are copied in logical order, and the header's data pointer is updated. The old data array is NOT freed — the language has no deallocation primitive, so growth leaks the previous array. Capacity never shrinks. Allocation failure: if nirmmita returns 0 during growth, the operation returns 0 (or ok[0] = 0) and the structure is UNCHANGED. suchi_srij returns 0 if either allocation fails. Out-of-bounds reads: suchi_grah returns 0 for i outside [0, len). 0 is a legal stored value, so check suchi_maap first when it matters. suchi_sangrah / suchi_nivesh / suchi_apanay return 1 ok / 0 out of bounds (or allocation failure for insert). chay_apanay / chay_avalok / avali_nishkas / avali_avalok return the value and set ok[0] (a 1-cell mala) to 1 on success, 0 when empty — the value alone cannot signal emptiness. All signatures stay within the 6-argument cap.
