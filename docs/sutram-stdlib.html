array

Real functions over raw memory (nirmmita/likh8/pad8). Each element is 8 bytes (one integer). The caller tracks the length; array_new only allocates. Safe variants take the element count and return 0 / do nothing on out-of-bounds access.

bigint

Arbitrary-precision integers as arrays of base-10 digits (0-9), least-significant digit first. All arrays are fixed size n; the caller allocates via nirmmita(n * 8) and tracks the size. Convention: bigint_mul requires res to have 2n digits (product of two n-digit numbers can need 2n digits). All other functions use n-digit arrays. Digits must be 0-9; behavior is undefined for out-of-range digits. bigint_zero(arr, n) — set all n digits to 0

chandas

After Pingala's Chandahśāstra (~2nd c. BCE). Sanskrit metre is built from two syllable weights — laghu (light) and guru (heavy) — so an n-syllable metre is a sequence of two choices: there are exactly 2^n of them. Pingala gave the doubling rule for 2^n, the Meru-prastāra (Pascal's triangle) to count how many metres have exactly k guru syllables, and the mātrā-meru, which generates the Fibonacci numbers. A pattern is carried as an integer bitmask: bit i (LSB = first syllable) is 1 for guru, 0 for laghu. The integer value IS the pattern's index in the prastāra.

ganita

After Aryabhata's Kuttaka (~499 CE) and the Chakravala of Jayadeva and Bhaskara II (~1150 CE). KUTTAKA ("the pulveriser") solves the linear indeterminate equation ax + by = c. It is the ancestor of the extended Euclidean algorithm. CHAKRAVALA ("the wheel") solves the quadratic indeterminate equation x^2 - N*y^2 = 1, known in Europe as Pell's equation. It was the first complete method for it, and for N = 61 it gives x = 1766319049, y = 226153980 - a case Europe first solved in 1657. kuttaka(a, b, c) -> x such that a*x is congruent to c (mod b). Requires gcd(a, b) to divide c. Returns x (a particular solution).

kalana

Built on typed `kosh dasham` parameters (T18) and the float fast paths (F1/F2/FG1/FC1). Every function READS its kosh parameters only — never `kosh_push` on a parameter, which the compiler deliberately rejects because the pointer is passed by value. Sutram has no first-class functions, so anything that would take a callback instead takes either SAMPLES (for integration/differentiation) or POLYNOMIAL COEFFICIENTS (for root finding). Coefficients are in ascending order: c[0] + c[1]*x + c[2]*x^2 + ... --------------------------------------------------------------- Integration over sampled data --------------------------------------------------------------- Trapezoidal rule. xs and ys are sample points and values; uses the shorter length.

madhava

After Madhava of Sangamagrama (~1340-1425 CE) and the Kerala school of astronomy and mathematics. Madhava gave infinite-series expansions for the sine, cosine and arctangent functions, and from the arctangent series a rapidly converging series for pi - more than two centuries before Newton, Gregory and Leibniz. These use T12 scalar floats (dasham). square root by Newton's method (Babylonian), to float precision

samanvaya

Sutram has no 2-D array type, so a matrix is a FLAT `kosh dasham` of m*n elements in row-major order, with the dimensions passed explicitly: A[i][j] == a[i * n + j] for an m x n matrix CONTRACT for output matrices: the caller must have pushed m*n elements already. A kosh's capacity is not its length, so out[i] is out of bounds until an element exists. Functions here never `kosh_push` a parameter — the compiler rejects that, correctly, because the pointer is passed by value. Inputs are read-only. Outputs are written in place and are visible to the caller. --------------------------------------------------------------- element access helpers (flat index) --------------------------------------------------------------- identity matrix: n x n, out must hold n*n elements

sankhyiki

The first library module built on typed `kosh dasham` parameters (T18). Every function takes a float array by parameter and only READS it — no kosh_push, because pushing to a kosh parameter is deliberately rejected by the compiler (the pointer is passed by value; growth would leave the caller with a stale pointer). Float arrays are the natural input here: statistics over integers would silently truncate. Use `kosh dasham` on the caller's side. Convention: variance and standard deviation are the POPULATION forms (divide by n). Multiply by n/(n-1) if you need the sample forms. --- sum ---
