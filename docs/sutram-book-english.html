1. What is Sutram?

Sutram (सूत्रम्) means "a thread" in Sanskrit — a thread that ties everything together. Sutram is a programming language whose keywords come from Sanskrit, whose compiler is written in pure assembly, and which compiles directly to x86-64 machine code. There is no interpreter, no virtual machine, and no runtime library between your program and the metal.

Why learn Sutram?

1. Simplicity of Python, speed of C. You write readable code with clean Sanskrit keywords; the compiler produces a tiny native binary that runs as fast as hand-written assembly.

2. You see everything. Because the compiler is one readable assembly patra (~9000 lines), you can study how a real compiler works: lexer → parser → code generator → ELF writer. Sutram is itself a compiler-writing tool — you can build the compiler for your next language in Sutram.

3. Your language, your words. With language packs you can write every keyword in Hindi, Telugu, Bengali, Tamil, and nine other Indian languages. The Sanskrit keywords are the default — the thread that holds all the languages together.

What you need: a Linux x86-64 system (or WSL on Windows). No other dependency — not even a C compiler. The compiler is a single self-contained binary.

2. Your First Program

Every Sutram program starts with mukhya() — the "main" thread of execution. Statements go inside it. Semicolons are optional; braces are optional for single statements; comments start with //.

mukhya()
    likha("Namaste, Sutram!\n")

Save this as namaste.sm (sm = Sutram), then compile and run:

$ sutram namaste.sm namaste.bin
Siddh: 97 byte sankalit
$ ./namaste.bin
Namaste, Sutram!
The compiler emits a complete, runnable ELF binary — about 90 bytes for this program. That is the whole program: prologue, your likha call, exit syscall. Nothing else.

3. Variables and Constants

Declare a variable with vitti ("a thought / a state"). Integers can be declared with anka (digit). Constants use sutra (a thread / formula):

mukhya()
    vitti x = 10
    x = x + 5
    likha(x)        // 15
    sutra pi = 314
    likha(pi / 100)  // 3
    likha("\n")

The first five variables live in registers (rbx, r12–r15) — the compiler assigns them automatically. More variables spill to the stack. You never manage memory for simple values.

Try it: declare vitti x = 10 then change it with x = x + 5. Variables are mutable; sutra constants are folded at compile time.

4. Operators and Precedence

Sutram has the full operator sangrah you expect, with standard mathematical precedence:

OperatorMeaningExample
+ - * / %arithmetic, modulo17 % 5 → 2
== != < > <= >=comparisonx >= 18
&& ||logical and / ora > 0 && b > 5
& | ^bitwise2 & 12 → 0
( ... )grouping(3 + 4) * 2 → 14

Parentheses override precedence, exactly as in mathematics:

mukhya()
    vitti a = 3
    vitti b = 4
    likha((a + b) * 2)   // 14
    likha("\n")
    likha(17 % 5)         // 2
    likha("\n")
    likha(2 & 12)         // 0  (bitwise AND)
    likha("\n")
Precedence from lowest to highest: || → && → comparisons → + - & | ^ → * / %. Use parentheses when in doubt — they cost zero performance.

5. Making Decisions: yadi / anya

yadi (if) runs a block when a condition is true; anya (else) runs otherwise. Chain conditions with repeated yadi:

mukhya()
    vitti mulya = 0
    yadi (mulya > 0) {
        likha("Positive\n")
    } yadi (mulya < 0) {
        likha("Negative\n")
    } anya {
        likha("Zero\n")
    }

For comparing one value against many cases, use guna (quality / switch) with bhavana (a state / case):

mukhya()
    vitti divasa = 3
    guna (divasa) {
        bhavana 1: { likha("Somvaar\n") }
        bhavana 2: { likha("Mangalvaar\n") }
        bhavana 3: { likha("Budhvaar\n") }
        anya: { likha("Anyo divaah\n") }
    }

6. Loops: chakra, yavat, krama, agrim

chakra (repetition) is the counting loop — it means "for i = a to b":

mukhya()
    chakra i = 1 tak 5 {
        likha(i)
        likha(" ")   // 1 2 3 4 5
    }
    likha("\n")

yavat (as long as) is the while loop. krama (order/sequence — break) exits the loop; agrim (aim — continue) skips to the next round:

mukhya()
    vitti yogam = 0
    chakra i = 1 tak 100 {
        yadi (i > 10) { krama }
        yadi (i % 2 == 0) { agrim }
        yogam = yogam + i
    }
    likha(yogam)     // 25
    likha("\n")
This program sums the odd numbers from 1 to 10: when i > 10, krama stops the loop; when i is even, agrim skips it. The answer is 25.

7. Functions: prakriya

A prakriya (a process / procedure) is a named block that takes up to three arguments and returns a value with prati:

prakriya vishalya(mulya)
    prati mulya * mulya

mukhya()
    vitti phalam = vishalya(7)
    likha(phalam)     // 49
    likha("\n")

Functions can call themselves — recursion works out of the box:

prakriya fib(n) {
    yadi (n < 2) { prati n }
    prati fib(n - 1) + fib(n - 2)
}

mukhya()
    likha(fib(10))     // 55
    likha("\n")

8. Arrays: mala

Pankti (पङ्क्ति) is Sanskrit for "a row" — a line of things. Declare an mala with mala and a size in brackets; mala tarika[5] allocates five 64-bit slots and gives you the pointer:

mukhya()
    mala tarika[5]
    chakra i = 0 tak 5 {
        tarika[i] = i * i
    }
    likha(tarika[4])     // 16
    likha("\n")

Indexing with arr[i] reads and writes directly through the pointer — one machine instruction, no bounds checks, C speed.

The older spelling vitti tarika[5] also works — mala is the Sanskrit-correct way to say it.

9. Enums and Constants: ganana, sutra

ganana (creation) defines named integer constants — an enum:

mukhya()
    ganana LAAL = 1
    ganana HARA = 2
    ganana NEELA = 3
    vitti mera_ranga = HARA
    guna (mera_ranga) {
        bhavana 1: { likha("Red\n") }
        bhavana 2: { likha("Green\n") }
        bhavana 3: { likha("Blue\n") }
    }

Combine with guna for readable state machines. sutra declares a single compile-time constant — the compiler folds it into the generated code.

10. The Sutram Shell (REPL)

Version 1.0 ships an interactive shell — like Python's IDLE, but for Sutram. Start it with sutram -i:

$ sutram -i
Sutram khol v1.0 - sampurna sutra
Sutram kathan likho aur Enter dabao. Turant chalega.
Aadesh: sahayata (sahay) | nirgat (nikas) | sarvam (dekho)

sutra> vitti x = 21
Siddh: 54 byte sankalit
sutra> likha(x / 3)
Siddh: 201 byte sankalit
7
sutra> nirgat

Every line you type is added to a growing session program, compiled, and run instantly. Variables persist between lines — x sangrah on one line is there on the next.

Shell commands: sahayata (help) · sarvam (show the whole session) · nirgat (exit)

12. Errors and Debugging

Sutram reports parse errors with the line number and the exact token where it got stuck:

$ cat galat.sm
mukhya() {
    vitti x = 5
    vitti y = (x
    likha(x)
}
$ ./sutram_compiler galat.sm out.bin

Sutram Error: vyakaran dosh, pankti 4:5, shabd 'likha'
      likha(x)
      ^
Sanket: is sthan par shabd aur vyakaran dekho.

The exit code is 1 on a compile error, 0 on success — so build scripts can react.

Debug workflow: 1. Read the line number. 2. Check spelling of the keyword named in the error. 3. Try the same line in the shell (sutram -i) — errors show instantly without leaving your flow.

Under the hood

Sutram compiles to a position-independent ELF binary with this prologue: push rbp; push rbx; push r12–r15; mov rbp, rsp — the same registers your variables use. On exit: restore and syscall exit(0). The compiler itself is ~9000 lines of NASM you can read in an afternoon.

14. New Features: v22

Comments

Two styles — # (gudh) and // (dvigun slash). The compiler ignores them completely.

# this is a gudh comment
vitti x = 10  # works after code too
// this is a slash comment
likha(x)

Compound Assignment

vitti x = 100
x += 50   # 150
x -= 30   # 120
x *= 2    # 240
x /= 4    # 60
x %= 7    # 4

Increment / Decrement (++ / --)

vitti n = 5
n++      # n = 6
n--      # n = 5

String Concatenation

Strings and numbers join at compile time:

likha("Hello " + "World\n")
likha("The answer: " + 42 + "\n")
likha(7 + " days\n")

lkhb() — print without newline

likha() adds a newline after a number; lkhb() does not — ideal for tables:

chakra i = 1 tak 5 {
    lkhb(i)
    likha(" ")
}

Descending Loops

If the start value is greater than the end value, the loop counts down automatically:

chakra i = 5 tak 1 {
    lkhb(i)
    likha(" ")
}    # output: 5 4 3 2 1

yantra() — inline machine code

yantra("B8 3C 00 00 00")  # mov eax, 60
yantra("BF 2A 00 00 00")  # mov edi, 42
yantra("0F 05")            # syscall → exit(42)

grahan() and end of input

When input ends, grahan() now returns -1, so programs can exit cleanly:

vitti a = grahan()
yadi (a == -1) {
    likha("Input ended\n")
    krama
}

v29 – v41

Since this edition was written, Sutram has gained a ternary operator, a do-while loop, mala length and bounds checking, functions with up to six arguments, and a standard library. An out-of-range mala index is now a clean error instead of silent corruption, and keyboard input works in Windows programs. Every example below is checked by the project's own test suite.

17. Windows Setup — a complete guide

Sutram treats Windows as a first-class target, exactly like Linux. Everything in the earlier chapters works the same way; only the installation step differs, and that is what this chapter covers in full.

17.1 What you get

  • sutram.exe — the compiler as a native Win64 program (PE32+).
  • Compiled programs are real Windows executables, not scripts.
  • No WSL, no Linux VM, no Python, no C runtime. Nothing extra to install.
  • The same single compiler source builds both the Windows and Linux compilers, so the language behaves identically on both.

17.2 Requirements

  • Windows 10 or 11, 64-bit.
  • Nothing else for normal use. NASM is needed only if you build the compiler yourself.

17.3 Install — Method A: the wizard (recommended)

  1. Get Sutram-Setup.exe.
  2. Double-click it. Windows may show a SmartScreen prompt for a new program: choose More info → Run anyway.
  3. The wizard asks for a destination folder. The default is C:\Program Files\Sutram. Accept it, or use Browse to choose your own.
  4. Tick “Add Sutram to PATH” if you want to type sutram from any folder. This is recommended.
  5. Optionally choose a Start Menu entry and a Desktop shortcut.
  6. Press Install. When it finishes, close the wizard.

Windows then registers Sutram in Apps & Features, so you can repair, upgrade or uninstall it later from Settings.

17.4 Install — Method B: the portable folder

  1. Unzip sutram-windows-native.zip anywhere, e.g. C:\Sutram.
  2. Keep the folder together — the language packs live in lang\ next to sutram.exe.
  3. Open a terminal in that folder (Shift + right-click → Open in Terminal).
  4. Optionally run install.bat once, which adds the folder to PATH.

17.5 Install — Method C: build from source

For developers. Needs NASM and a PE-capable linker (GNU ld, MSVC, or lld-link):

nasm -f win64 -dWINDOWS -I. src\sutram_compiler.asm -o sutram.obj
ld -mi386pep --entry=_start -o sutram.exe sutram.obj

To build the wizard installer as well you need MinGW GCC and PowerShell; the scripts are in windows\ (run BUILD-WINDOWS-SETUP.cmd).

17.6 Understanding PATH

PATH is the suchi of folders Windows searches when you type a command. If Sutram's folder is on PATH, you can type sutram from anywhere; otherwise you must type the full path or be in the folder.

To check: open a new terminal and run sutram --version. If it prints the version, PATH is sangrah. If not, either re-run the installer with the PATH option, or run sutram.exe from the folder that contains it.

17.7 Your first Windows program

Create a patra namaste.sm:

# my first Windows program
mukhya()
    likha("Namaste, Windows!")

Compile and run it:

sutram.exe namaste.sm namaste.exe
namaste.exe

Output:

Namaste, Windows!

The output name decides the target: .exe makes a Windows executable, .bin makes a Linux one. One compiler, two targets.

17.8 What the generated .exe contains

A compiled program is one PE32+ section holding:

[PE headers][small runtime][your compiled code]

The runtime finds kernel32 at startup by walking the process environment block and reading its export table, so the program has no import table and no external dependencies. It maps the compiler's output, input and exit operations onto WriteFile, ReadFile and ExitProcess. Nothing has to be installed to run a Sutram-made .exe.

17.9 Language packs on Windows

Sutram is looked up in two places: lang\<name>.lang relative to the current folder, then %USERPROFILE%\.local\share\sutram\lang\. Put your packs in the second location and they work from any folder.

sutram.exe --lang gujarati prog.sm out.exe

The ten packs are Bengali, Gujarati, Hindi, Kannada, Malayalam, Marathi, Odia, Punjabi, Tamil and Telugu. Devanagari spellings of the keywords are also accepted.

17.11 Where to keep your projects

Anywhere you like. Two habits save trouble: avoid very deep paths, and quote paths that contain spaces — sutram.exe "C:\My Files\a.sm" "C:\out\a.exe". Unicode folder names work; the compiler opens files with the Windows API.

17.13 Update and uninstall

To upgrade: run a newer Sutram-Setup.exe — it detects the existing install and replaces it safely. To remove: Settings → Apps → Installed apps → Sutram → Uninstall. The uninstaller removes only the files it installed and leaves anything you created yourself.

17.16 Philosophy, unchanged

The compiler stays one pure-NASM source with no C, Python or runtime dependency; Sanskrit remains the core with native words for every Indian language; generated programs are native machine code, never interpreted; and the end user needs no toolchain. The installer is only packaging — it is not part of the language.

18. What is new — the current language

This chapter was added after the rest of the book. Everything in it is part of the language today and has been verified against known answers, not just compiled once. If an earlier chapter does not mention something here, this chapter is the more current.

Floating-point numbers — dasham / दशम

A variable may hold a 64-bit IEEE-754 floating-point number. Declare it with dasham; a literal with a decimal point is a float automatically.

dasham x = 1.5
dasham y = 2.25
likha(x + y)      # 3.750000

Floats mix with integers (the integer is promoted), support all four arithmetic operators and all six comparisons, and print with six decimal places. Functions can return a float — the compiler infers that from what they return.

Growable arrays — kosh / कोश

An ordinary mala (mala) is fixed in size. A kosh grows: it starts at a small capacity and doubles as needed.

kosh xs[4]              # capacity 4, length 0
kosh_push(xs, 10)
kosh_push(xs, 20)
likha(kosh_len(xs))    # 2
likha(xs[0])            # 10
dasham last = kosh_pop(xs)

Capacity is not length. kosh xs[4] has capacity 4 but length 0, so xs[0] is out of bounds until something is pushed. This trips people up once; it is deliberate, and it is what makes indexing safe.

Typed arrays — kosh dasham

A kosh can be declared to hold floats. Integer values pushed into it are promoted, and its elements behave as floats everywhere.

kosh dasham temps[4]
kosh_push(temps, 36.6)
kosh_push(temps, 37)      # promoted to 37.0
likha(temps[1])            # 37.000000

Typed function parameters

A function can require a particular kind of argument, and the compiler checks it.

prakriya mean(kosh dasham xs) {
    dasham s = 0.0
    vitti i = 0
    yavat (i < kosh_len(xs)) {
        s = s + xs[i]
        i = i + 1
    }
    prati s / kosh_len(xs)
}

A kosh dasham is passed as a pointer, so indexed writes are visible to the caller — a function can fill an mala for you. But growing it is not allowed: calling kosh_push on a parameter is refused with a named error, because the pointer is passed by value and the caller would be left holding a stale one. This is a deliberate safety boundary, not a missing feature.

The Sutram IDE

Installed with the language. A single native program — no Python, no interpreter — with:

  • a code editor with line numbers and syntax highlighting;
  • Ctrl-R to compile and run what you have written, with the output shown below;
  • Ctrl-E to browse the example programs one at a time;
  • Ctrl-T for an interactive shell — type a statement, press Enter, see it run. The session remembers earlier lines, so you can build something up a step at a time;
  • Ctrl-S save, Ctrl-L load, Ctrl-Q quit.

On Windows the IDE is not yet available; use the interactive shell (sutram -i) instead.

Speed, measured rather than claimed

The compiler keeps variable values in processor registers instead of memory. On a representative numerical program this produced a measured speed-up of about 1.2× across recent rounds, and on a tight integer loop the generated code went from 13 instructions to 5 — a measured 4.9×. Every claim in this section was measured on the same machine before and after, not estimated.

What the project is careful about

Four memory-corruption bugs were found and fixed, each now covered by a permanent test. The compiler is checked by 160 tests and by twelve code-shape gates that assert how much code a given construct is allowed to produce. Where the project cannot verify something — Windows has not yet been run on a real Windows machine — it says so plainly rather than implying otherwise.
