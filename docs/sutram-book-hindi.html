सूत्रम् पुस्तक

प्रस्तावना. Sutram एक प्रोग्रामिंग लैंग्वेज है जिसके कीवर्ड्स संस्कृत के हैं - यह सिर्फ सजावट के लिए नहीं, बल्कि इसके डिज़ाइन का एक पक्का वादा है। इसके नाम, Sutram, का मतलब है 'सूत्र': पाणिनी की Ashtadhyayi (दुनिया का पहला फॉर्मल ग्रामर) का छोटा और नियम-आधारित रूप। इसकी स्टैंडर्ड लाइब्रेरी सीधे तौर पर भारतीय गणितीय परंपरा को लागू करती है - जैसे पिंगला का बाइनरी और Meru-prastara, आर्यभट्ट का kuttaka, और भास्कर का chakravala। और इसका कंपाइलर खुद में पूरा है: एक हाथ से लिखी गई असेंबली फाइल जो सीधे नेटिव मशीन कोड बनाती है, और इसमें आपको किसी रनटाइम या टूलचेन की ज़रूरत नहीं पड़ती। यह किताब इस लैंग्वेज को बिल्कुल शुरुआत से सिखाती है। हर उदाहरण असली कोड है जिसे कंपाइल और रन किया जा सकता है, और लैंग्वेज के बारे में हर दावे को आप खुद चेक कर सकते हैं।
💡 इस्तेमाल की विधि: केसरिया बिंदुओं वाले शब्द पर माउस ले जाइए — उसका संस्कृत शब्द और English अर्थ तुरंत दिखेगा. (मोबाइल में शब्द पर टैप करके रखें. छपे पन्ने के लिए हर अध्याय के अंत में तालिका है.)

संस्कृत कूटशब्द। नेटिव मशीन कोड। हर भाषा को जोड़ने वाला एक धागा।

1. सूत्रम् क्या है? (What is Sutram?)

सूत्रम् का अर्थ है "धागा" — जो सबको जोड़े। सूत्रम् एक क्रमादेशन भाषा है जिसके कूटशब्द संस्कृत से आते हैं, जिसका संकलक शुद्ध असेंबली में लिखा गया है, और जो सीधे x86-64 मशीन कोड में बदलती है। न कोई इंटरप्रेटर, न वर्चुअल मशीन, न कोई रनटाइम लाइब्रेरी।

क्यों सीखें सूत्रम्?

1. पायथन जैबी सरलता, C जैसी गति। आप साफ-सुथरे संस्कृत कूटशब्द से पढ़ने योग्य कोड लिखते हैं; संकलक एक छोटा नेटिव बाइनरी बनाता है जो हाथ से लिखी असेंबली जितनी तेज़ चलता है।

2. सब कुछ दिखता है। संकलक एक पढ़ने योग्य असेंबली फ़ाइल (~9000 पंक्तियाँ) है — आप देख सकते हैं कि असली संकलक कैसे काम करता है: लेक्सर → पार्सर → कोड जनरेटर → ELF लेखक।

3. आपकी भाषा, आपके शब्द। भाषा-संकुल से आप हर कूटशब्द हिन्दी, तेलुगु, बंगाली, तमिल और नौ अन्य भारतीय भाषाओं में लिख सकते हैं। संस्कृत कूटशब्द मूल हैं — वही धागा है जो सब भाषाओं को बांधता है।

क्या चाहिए: Linux x86-64 सिस्टम (या Windows पर WSL)। कोई और निर्भरता नहीं — C संकलक भी नहीं।

2. आपका पहला क्रमादेश (Your first program)

हर सूत्रम् क्रमादेश mukhya() से शुरू होता है — चलने की "मुख्य" धारा। सेमीकोलन वैकल्पिक हैं; एक कथन के लिए ब्रेस भी वैकल्पिक हैं; टिप्पणी // से शुरू होती है।

mukhya()
    likha("Namaste, Sutram!\n")

इसे namaste.sm नाम से सेव करें, फिर कम्पाइल कर चलाएँ:

$ sutram namaste.sm namaste.bin
Siddh: 97 byte sankalit
$ ./namaste.bin
Namaste, Sutram!
संकलक एक पूर्ण, चलने योग्य ELF बाइनरी बनाता है — इस क्रमादेश के लिए मात्र 90 बाइट। उतना ही पूरा क्रमादेश: प्रोलॉग, आपका likha कॉल, exit syscall।

3. चर और अचर (Variables and constants)

vitti ("एक वृत्ति / अवस्था") से चर बनाएँ। पूर्णांक के लिए anka। अचर के लिए sutra:

mukhya()
    vitti x = 10
    x = x + 5
    likha(x)        // 15
    sutra pi = 314
    likha(pi / 100)  // 3
    likha("\n")

पहले पाँच चर रजिस्टरों (rbx, r12–r15) में रहते हैं — संकलक स्वयं नियत करता है। आगे के चर स्टैक पर जाते हैं। साधारण मानों के लिए आपको स्मृति प्रबंधन की चिंता नहीं करनी पड़ती।

4. संक्रियाएँ और पूर्वता (Operators and precedence)

सूत्रम् में पूरी संक्रिया-सूची है, गणित के मानक नियमों के साथ:

OperatorMeaningExample
+ - * / %arithmetic, modulo17 % 5 → 2
== != < > <= >=comparisonx >= 18
&& ||logical and / ora > 0 && b > 5
& | ^bitwise2 & 12 → 0
( ... )grouping(3 + 4) * 2 → 14

कोष्ठक पूर्वता बदल देते हैं — बिल्कुल गणित की तरह:

mukhya()
    vitti a = 3
    vitti b = 4
    likha((a + b) * 2)   // 14
    likha("\n")
    likha(17 % 5)         // 2
    likha("\n")
    likha(2 & 12)         // 0  (bitwise AND)
    likha("\n")
पूर्वता (निम्न से उच्च): || → && → तुलना → + - & | ^ → * / %। शक हो तो कोष्ठक लगाएँ — प्रदर्शन पर कोई खर्च नहीं।

5. निर्णय: yadi / anya (Decisions (if / else))

yadi (यदि) शर्त सच होने पर ब्लॉक चलाता है; anya (अन्यत्र) अन्यथा। श्रृंखला बनाने के लिए बार-बार yadi लिखें:

mukhya()
    vitti mulya = 0
    yadi (mulya > 0) {
        likha("Positive\n")
    } yadi (mulya < 0) {
        likha("Negative\n")
    } anya {
        likha("Zero\n")
    }

एक मान की अनेक स्थितियों से तुलना के लिए guna (गुण — switch) और bhavana (भावना — case) उपयोग करें:

mukhya()
    vitti divasa = 3
    guna (divasa) {
        bhavana 1: { likha("Somvaar\n") }
        bhavana 2: { likha("Mangalvaar\n") }
        bhavana 3: { likha("Budhvaar\n") }
        anya: { likha("Anyo divaah\n") }
    }

6. पाश: chakra, yavat, krama, agrim (Loops)

chakra (पुनरावृत्ति) गिनती वाला पाश है — "i = a से b तक":

mukhya()
    chakra i = 1 tak 5 {
        likha(i)
        likha(" ")   // 1 2 3 4 5
    }
    likha("\n")

yavat (यावत् — जब तक) while-पाश है। krama (क्रम — break) पाश तोड़ता है; agrim (उद्देश्य — continue) अगले चरण पर जाता है:

mukhya()
    vitti yogam = 0
    chakra i = 1 tak 100 {
        yadi (i > 10) { krama }
        yadi (i % 2 == 0) { agrim }
        yogam = yogam + i
    }
    likha(yogam)     // 25
    likha("\n")
यह क्रमादेश 1 से 10 तक विषम संख्याओं का योग निकालता है: जब i > 10, krama पाश रोकता है; जब i सम है, agrim उसे छोड़ता है। उत्तर: 25।

7. फलन: prakriya (Functions)

prakriya (प्रक्रिया) एक नामित ब्लॉक है जो तीन तर्क तक लेता है और prati से मान लौटाता है:

prakriya vishalya(mulya)
    prati mulya * mulya

mukhya()
    vitti phalam = vishalya(7)
    likha(phalam)     // 49
    likha("\n")

फलन स्वयं को कॉल कर सकते हैं — पुनरावृत्ति सीधे काम करती है:

prakriya fib(n) {
    yadi (n < 2) { prati n }
    prati fib(n - 1) + fib(n - 2)
}

mukhya()
    likha(fib(10))     // 55
    likha("\n")

8. सारणी: mala (Arrays)

पङ्क्ति का अर्थ है "पंक्ति" — चीज़ों की एक कतार। mala से सारणी बनाएँ: mala tarika[5] पाँच 64-बिट स्थान देता है और पॉइंटर देता है:

mukhya()
    mala tarika[5]
    chakra i = 0 tak 5 {
        tarika[i] = i * i
    }
    likha(tarika[4])     // 16
    likha("\n")

arr[i] से सीधे पॉइंटर से पढ़ा-लिखा जाता है — एक मशीन निर्देश, C की गति।

पुरानी वर्तनी vitti tarika[5] भी चलती है — mala संस्कृत-शुद्ध रूप है।

9. enum और अचर: ganana, sutra (Enums and constants)

ganana (सृजन) नामित पूर्णांक अचर बनाता है — एक enum:

mukhya()
    ganana LAAL = 1
    ganana HARA = 2
    ganana NEELA = 3
    vitti mera_ranga = HARA
    guna (mera_ranga) {
        bhavana 1: { likha("Red\n") }
        bhavana 2: { likha("Green\n") }
        bhavana 3: { likha("Blue\n") }
    }

guna के साथ मिलाकर पढ़ने योग्य स्टेट-मशीन बनाएँ। sutra एकल संकलन-समय अचर है — संकलक उसे कोड में ही समा देता है।

10. सूत्रम् कवच (REPL) (The Sutram shell (REPL))

संस्करण 1.0 में एक संवादी कवच आती है — पायथन के IDLE जैसी। चलाएँ: sutram -i:

$ sutram -i
Sutram khol v1.0 - sampurna sutra
Sutram kathan likho aur Enter dabao. Turant chalega.
Aadesh: sahayata (sahay) | nirgat (nikas) | sarvam (dekho)

sutra> vitti x = 21
Siddh: 54 byte sankalit
sutra> likha(x / 3)
Siddh: 201 byte sankalit
7
sutra> nirgat

आपकी हर पंक्ति एक बढ़ते सत्र-क्रमादेश में जुड़ती है, तुरंत कम्पाइल होती है और चलती है। चर पंक्तियों के बीच बने रहते हैं — एक पंक्ति पर सेट किया x अगली पंक्ति पर मिलता है।

कवच आदेश: sahayata (सहायता) · sarvam (पूरा सत्र दिखाएँ) · nirgat (बाहर)

14. नई विशेषताएँ: v22 (New features)

टिप्पणियाँ (Comments)

क्रमादेश में टिप्पणी लिखने के दो तरीके हैं — # (हैश) और // (डबल स्लैश)। संकलक इन्हें पूरी तरह अनदेखा कर देता है।

# यह हैश टिप्पणी है
vitti x = 10  # कोड के बाद भी लिख सकते हैं
// यह स्लैश टिप्पणी है
likha(x)

संयुक्त असाइनमेंट (Compound Assignment)

चर को उसी के मान पर कोई संक्रिया करके परिणाम वापस उसी में रखना:

vitti x = 100
x += 50   # 150
x -= 30   # 120
x *= 2    # 240
x /= 4    # 60
x %= 7    # 4

वृद्धि और क्षय (++ / --)

vitti n = 5
n++      # n = 6
n--      # n = 5

सूत्र-संयोजन (String Concatenation)

संकलन-काल पर ही सूत्र और संख्या जुड़ जाते हैं:

likha("नमस्ते " + "दुनिया\n")
likha("उत्तर: " + 42 + "\n")
likha(7 + " दिन\n")

lkhb() — बिना नई पंक्ति के मुद्रण

likha() संख्या के बाद नई पंक्ति छोड़ता है; lkhb() नहीं छोड़ता — सारणी बनाने के लिए:

chakra i = 1 tak 5 {
    lkhb(i)
    likha(" ")
}

घटते लूप (Descending Loops)

प्रारंभ मान अंतिम मान से बड़ा हो, तो गणना स्वतः उलट जाती है:

chakra i = 5 tak 1 {
    lkhb(i)
    likha(" ")
}    # आउटपुट: 5 4 3 2 1

yantra() — इनलाइन मशीन-कोड

कच्चे x86-64 बाइट सीधे उत्पन्न कोड में डालें:

yantra("B8 3C 00 00 00")  # mov eax, 60
yantra("BF 2A 00 00 00")  # mov edi, 42
yantra("0F 05")            # syscall → exit(42)

grahan() और इनपुट का अंत

इनपुट खत्म होने पर grahan() अब -1 लौटाता है, जिससे क्रमादेश साफ़-साफ़ बंद हो सकता है:

vitti a = grahan()
yadi (a == -1) {
    likha("इनपुट समाप्त\n")
    krama
}

15. तकनीकी शब्दकोश (Technical Glossary) (Technical glossary)

इस पुस्तक में प्रयुक्त तकनीकी शब्दों के प्रामाणिक हिन्दी रूप — और उनका कारण:

Program → क्रमादेश — क्रम (क्रमबद्ध) + आदेश (command) = क्रमबद्ध आदेशों का समूह। वैज्ञानिक तथा तकनीकी शब्दावली आयोग (CSTT) का प्रामाणिक शब्द; "प्रोग्राम" केवल अंग्रेज़ी का लिप्यंतरण है।

Compiler → संकलक — स्रोत-कोड को यंत्र-कोड में बदलने वाला अनुवादक। संकलन का अर्थ है एकत्र करके तैयार करना — यही यह करता है।

Computer → संगणक — सम् + गणक = गणना करने वाला। आधुनिक हिन्दी में सरकारी और शैक्षिक प्रयोग का प्रामाणिक शब्द।

Keyword → कूटशब्द — कूट (code) + शब्द। भाषा के लिए आरक्षित विशेष शब्द, जिन्हें चर-नाम के रूप में इस्तेमाल नहीं किया जा सकता।

Variable → चर — जिसका मान चलते-चलते बदल सकता है। गणित की सदियों पुरानी परंपरा से आया प्रामाणिक शब्द।

Constant → अचर — स्थिर (जो नहीं बदलता) + अंक। गणित में व्यापक प्रचलित; "अचल" भी पर्याय है।

Function → फलन — फल (परिणाम) देने वाला: इनपुट से आउटपुट का नियम। गणित और संगणक विज्ञान दोनों में प्रामाणिक।

Loop → पाश — दोहराव वाली संरचना; धागे की आकृति से नाम। "पुनरावृत्ति" इसका अधिक औपचारिक विकल्प है।

Array → सारणी — पंक्तिबद्ध मानों का समूह। सूत्रम् में इसी के लिए mala (पंक्ति) कूटशब्द है।

Memory → स्मृति — डेटा संग्रह करने का स्थान। "मेमोरी" केवल ध्वन्यात्मक उच्चारण है, अर्थ नहीं देता।

Machine Code → यंत्र-कोड — CPU द्वारा सीधे निष्पादित होने वाला द्विआधारी कोड। सूत्रम् सीधे इसी पर संकलित होता है।

String → सूत्र — अक्षरों की माला। संस्कृत में सूत्र का शाब्दिक अर्थ ही धागा है — इसीलिए भाषा का नाम सूत्रम् है!

Error → त्रुटि — क्रमादेश में गलती। संकलक इसे पंक्ति-संख्या के साथ बताता है।

Debugging → दोषसुधार — दोष (bug) खोजकर ठीक करने की प्रक्रिया।

Language → भाषा — क्रमादेशन भाषा: जिसमें मनुष्य सोचकर संगणक को आदेश देता है।

16. संस्कृत मूल: आपकी भाषा में जीवित शब्द (Sanskrit roots)

सूत्रम् का प्रत्येक कूटशब्द संस्कृत की किसी धातु से आया है — और वही शब्द आपकी भाषा में आज भी जीवित है। जब आप shunya लिखते हैं, तो आप उसी शब्द को छूते हैं जो अरबी होते हुए अंग्रेज़ी का zero बना।

17. विंडोज़ पर स्थापना — पूर्ण मार्गदर्शिका

सूत्रम् विंडोज़ को लिनक्स की तरह ही प्रथम-श्रेणी का लक्ष्य मानता है। पहले के सभी अध्याय वैसे ही काम करते हैं; केवल स्थापना का चरण बदलता है, और वही इस अध्याय में पूरा समझाया गया है।

17.1 आपको क्या मिलता है

  • sutram.exe — संकलक, जो मूल Win64 क्रमादेश (PE32+) है।
  • संकलित क्रमादेश वास्तविक विंडोज़ कार्यक्रम होते हैं, स्क्रिप्ट नहीं।
  • WSL, लिनक्स VM, पाइथन या C रनटाइम की आवश्यकता नहीं।
  • एक ही संकलक स्रोत से विंडोज़ और लिनक्स दोनों संकलक बनते हैं, इसलिए भाषा का व्यवहार दोनों पर समान है।

17.2 आवश्यकताएँ

  • विंडोज़ 10 या 11, 64-बिट।
  • सामान्य उपयोग के लिए और कुछ नहीं। NASM केवल तब चाहिए जब आप संकलक स्वयं बनाएँ।

17.3 स्थापना — विधि क: जादूगर (अनुशंसित)

  1. Sutram-Setup.exe प्राप्त करें।
  2. उस पर डबल-क्लिक करें। नए क्रमादेश के लिए विंडोज़ SmartScreen चेतावनी दिखा सकता है: More info → Run anyway चुनें।
  3. जादूगर गंतव्य फ़ोल्डर पूछेगा। डिफ़ॉल्ट C:\Program Files\Sutram है। उसे स्वीकारें या Browse से अपना चुनें।
  4. यदि किसी भी फ़ोल्डर से sutram लिखना चाहते हैं तो “Add Sutram to PATH” चुनें। यह अनुशंसित है।
  5. चाहें तो Start Menu प्रविष्टि और Desktop शॉर्टकट चुनें।
  6. Install दबाएँ। पूरा होने पर जादूगर बंद करें।

इसके बाद सूत्रम् Apps & Features में दर्ज हो जाता है, इसलिए आगे आप Settings से मरम्मत, अद्यतन या अनइंस्टॉल कर सकते हैं।

17.4 स्थापना — विधि ख: पोर्टेबल फ़ोल्डर

  1. sutram-windows-native.zip को कहीं भी खोलें, जैसे C:\Sutram।
  2. फ़ोल्डर साथ रखें — भाषा-पैक sutram.exe के पास lang\ में रहते हैं।
  3. उसी फ़ोल्डर में टर्मिनल खोलें (Shift + दायाँ-क्लिक → Open in Terminal)।
  4. चाहें तो एक बार install.bat चलाएँ, जो फ़ोल्डर को PATH में जोड़ देता है।

17.5 स्थापना — विधि ग: स्रोत से निर्माण

विकासकर्ताओं के लिए। NASM और PE-सक्षम लिंकर (GNU ld, MSVC या lld-link) चाहिए:

nasm -f win64 -dWINDOWS -I. src\sutram_compiler.asm -o sutram.obj
ld -mi386pep --entry=_start -o sutram.exe sutram.obj

जादूगर संस्थापक भी बनाना हो तो MinGW GCC और PowerShell चाहिए; स्क्रिप्ट windows\ में हैं (BUILD-WINDOWS-SETUP.cmd चलाएँ)।

17.6 PATH को समझें

PATH उन फ़ोल्डरों की सूची है जिन्हें विंडोज़ कमांड टाइप करते समय खोजता है। यदि सूत्रम् का फ़ोल्डर PATH में है तो आप कहीं से भी sutram लिख सकते हैं; अन्यथा पूरा पथ लिखना होगा या उसी फ़ोल्डर में रहना होगा।

जाँच: नया टर्मिनल खोलकर sutram --version चलाएँ। संस्करण दिखे तो PATH ठीक है। न दिखे तो PATH विकल्प के साथ संस्थापक दोबारा चलाएँ, या जिस फ़ोल्डर में sutram.exe है वहाँ से चलाएँ।

17.7 आपका पहला विंडोज़ क्रमादेश

फ़ाइल namaste.sm बनाएँ:

# मेरा पहला विंडोज़ क्रमादेश
mukhya()
    likha("नमस्ते, विंडोज़!")

संकलित करें और चलाएँ:

sutram.exe namaste.sm namaste.exe
namaste.exe

आउटपुट:

नमस्ते, विंडोज़!

आउटपुट का नाम लक्ष्य तय करता है: .exe से विंडोज़ कार्यक्रम, .bin से लिनक्स। एक संकलक, दो लक्ष्य।

17.8 बने .exe में क्या होता है

संकलित क्रमादेश एक PE32+ खंड होता है जिसमें होते हैं:

[PE शीर्षक][छोटा रनटाइम][आपका संकलित कोड]

रनटाइम प्रारंभ में प्रक्रिया-पर्यावरण ब्लॉक से चलकर और उसकी निर्यात-सारणी पढ़कर kernel32 खोज लेता है, इसलिए क्रमादेश में कोई आयात-सारणी और कोई बाहरी निर्भरता नहीं होती। यह आउटपुट, इनपुट और निकास को WriteFile, ReadFile और ExitProcess पर ले जाता है। सूत्रम् से बने .exe को चलाने के लिए कुछ भी स्थापित करने की आवश्यकता नहीं।

17.9 विंडोज़ पर भाषा-पैक

सूत्रम् दो जगह देखता है: वर्तमान फ़ोल्डर के सापेक्ष lang\<name>.lang, फिर %USERPROFILE%\.local\share\sutram\lang\। पैक दूसरी जगह रखें तो वे किसी भी फ़ोल्डर से काम करेंगे।

sutram.exe --lang gujarati prog.sm out.exe

दस पैक: बंगाली, गुजराती, हिन्दी, कन्नड़, मलयालम, मराठी, ओड़िया, पंजाबी, तमिल, तेलुगु। कूटशब्दों की देवनागरी वर्तनी भी स्वीकार्य है।

17.10 आदेश-संदर्भ

17.11 परियोजनाएँ कहाँ रखें

कहीं भी। दो आदतें परेशानी बचाती हैं: बहुत गहरे पथ से बचें, और स्पेस वाले पथ को उद्धरण में रखें — sutram.exe "C:\My Files\a.sm" "C:\out\a.exe"। यूनिकोड फ़ोल्डर नाम काम करते हैं; संकलक फ़ाइलें विंडोज़ API से खोलता है।

17.15 विंडोज़ पर अभी शेष

अभी काम करता है: संकलन, likha और shabda, गणित, चर, yadi/anya, yavat, chakra, krama/agrim, छह तर्कों तक के फलन, पुनरावर्तन, शीघ्र प्रत्यागमन, ब्लॉक टिप्पणियाँ, भाषा-पैक, त्रुटि-संदेश।

विंडोज़ पर कीबोर्ड इनपुट (grahan) अब काम करता है: बना हुआ .exe लिनक्स सिस्टम कॉल के बजाय एम्बेडेड रनटाइम (ReadFile) से पढ़ता है। सारणी (mala) और संरचना (rachana) VirtualAlloc से स्मृति लेते हैं। अभी भी पोर्ट नहीं हुआ है: नेटवर्क बिल्टइन्स। इंटरैक्टिव REPL इम्प्लीमेंट हो गया है और एक असली Windows मशीन पर चेक होने का इंतज़ार है।

17.16 दर्शन — अपरिवर्तित

संकलक एक शुद्ध-NASM स्रोत रहता है, जिसमें C, पाइथन या रनटाइम की निर्भरता नहीं; संस्कृत भाषा का केंद्र रहता है और हर भारतीय भाषा के लिए मूल शब्द हैं; बने क्रमादेश मूल मशीन-कोड होते हैं, कभी व्याख्यायित नहीं; और अंतिम उपयोगकर्ता को किसी टूलचेन की आवश्यकता नहीं। संस्थापक केवल पैकेजिंग है — वह भाषा का भाग नहीं है।

18. नया क्या है — वर्तमान भाषा

यह अध्याय बाकी किताब के बाद जोड़ा गया था। इसमें दी गई हर चीज़ आज भाषा का हिस्सा है और इसे ज्ञात उत्तरों के साथ सत्यापित किया गया है, न कि केवल एक बार कंपाइल किया गया है। यदि किसी पुराने अध्याय में यहाँ बताई गई किसी चीज़ का ज़िक्र नहीं है, तो यह अध्याय अधिक नया है।

फ्लोटिंग-पॉइंट नंबर — दशम

एक वेरिएबल में 64-बिट IEEE-754 फ्लोटिंग-पॉइंट नंबर हो सकता है। इसे दशम के साथ डिक्लेयर करें; दशमलव बिंदु वाला लिटरल अपने आप फ्लोट बन जाता है।

फ्लोट्स इंटीजर्स के साथ मिक्स होते हैं (इंटीजर प्रमोट हो जाता है), चारों अरिथमेटिक ऑपरेटर्स और सभी छह तुलनाओं (comparisons) को सपोर्ट करते हैं, और छह दशमलव स्थानों के साथ प्रिंट होते हैं। फंक्शन्स फ्लोट रिटर्न कर सकते हैं — कंपाइलर इसे उनके रिटर्न वैल्यू से समझ लेता है।

बढ़ने वाले ऐरे — कोश

एक साधारण ऐरे का आकार फिक्स होता है। कोश बढ़ता है: यह छोटी क्षमता (capacity) से शुरू होता है और ज़रूरत पड़ने पर दोगुना हो जाता है।

क्षमता (Capacity) लंबाई (length) नहीं है। 4 की क्षमता के साथ डिक्लेयर किए गए कोश की क्षमता 4 होती है लेकिन लंबाई 0 होती है, इसलिए जब तक कुछ पुश नहीं किया जाता, इंडेक्स 0 आउट ऑफ बाउंड्स रहता है। यह लोगों को एक बार उलझा देता है; यह जानबूझकर किया गया है, और इसी से इंडेक्सिंग सुरक्षित होती है।

टाइप्ड ऐरे — कोश दशम

कोश को फ्लोट्स रखने के लिए डिक्लेयर किया जा सकता है। इसमें पुश की गई इंटीजर वैल्यूज़ प्रमोट हो जाती हैं, और इसके एलिमेंट्स हर जगह फ्लोट्स की तरह काम करते हैं।

टाइप्ड फंक्शन पैरामीटर्स

एक फंक्शन किसी खास तरह के आर्गुमेंट की मांग कर सकता है, और कंपाइलर इसकी जांच करता है।

एक टाइप्ड फ्लोट ऐरे पॉइंटर के रूप में पास किया जाता है, इसलिए इंडेक्स्ड राइट्स कॉलर को दिखाई देते हैं — एक फंक्शन आपके लिए ऐरे भर सकता है। लेकिन इसे बढ़ाना (grow करना) अलाउड नहीं है: पैरामीटर पर कोश_पुश (kosh_push) कॉल करने से एक नेम्ड एरर के साथ मना कर दिया जाता है, क्योंकि पॉइंटर बाय वैल्यू पास किया जाता है और कॉलर के पास एक पुराना (stale) पॉइंटर रह जाएगा। यह एक जानबूझकर बनाई गई सुरक्षा सीमा है, कोई गायब फीचर नहीं।

स्टैंडर्ड लाइब्रेरी

कंपाइलर के साथ पंद्रह मॉड्यूल आते हैं। उन्हें आयोजन (yoj) के साथ इम्पोर्ट करें। वे अरिथमेटिक और नंबर थ्योरी; सॉर्टिंग और टेक्स्ट; पिंगल के छन्दशास्त्र; आर्यभट्ट और भास्कर के गणित; π, साइन, कोसाइन और स्क्वायर रूट के लिए केरल स्कूल की सीरीज़; स्टैटिस्टिक्स; न्यूमेरिकल कैलकुलस — इंटीग्रेशन, डेरिवेटिव्स और पॉलिनॉमियल रूट्स; मैट्रिसेस और डिटरमिनेंट्स के साथ लीनियर अल्जेब्रा; और फाइल पढ़ने और लिखने को कवर करते हैं।

इसे आज़माएं: हेरिटेज मॉड्यूल्स असली गणित की गणना करते हैं — 61 के चक्रवाल से x² − 61y² = 1 का सबसे छोटा हल मिलता है, जो x = 1766319049, y = 226153980 है। यह 7वीं सदी का तरीका है, जिसे सही उत्तर के साथ सत्यापित किया गया है।

सूत्रम IDE

भाषा के साथ इंस्टॉल होता है। एक सिंगल नेटिव प्रोग्राम — कोई Python नहीं, कोई इंटरप्रेटर नहीं — जिसमें लाइन नंबर और सिंटैक्स हाइलाइटिंग वाला कोड एडिटर है; आपने जो लिखा है उसे कंपाइल और रन करने के लिए Ctrl-R, आउटपुट नीचे दिखाई देता है; एक-एक करके उदाहरण प्रोग्राम देखने के लिए Ctrl-E; एक इंटरैक्टिव शेल के लिए Ctrl-T जहाँ आप एक स्टेटमेंट टाइप करते हैं, Enter दबाते हैं, और उसे रन होते देखते हैं, सेशन पिछली लाइनों को याद रखता है ताकि आप एक-एक कदम करके कुछ बना सकें; और सेव करने के लिए Ctrl-S, लोड करने के लिए Ctrl-L, छोड़ने के लिए Ctrl-Q।

Windows पर IDE अभी उपलब्ध नहीं है; इसके बजाय इंटरैक्टिव शेल का इस्तेमाल करें।

गति, दावा करने के बजाय मापी गई

कंपाइलर वेरिएबल की वैल्यूज़ को मेमोरी के बजाय प्रोसेसर रजिस्टर्स में रखता है। एक प्रतिनिधि न्यूमेरिकल प्रोग्राम पर इससे हाल के राउंड्स में लगभग 1.2 गुना की मापी गई गति (speed-up) मिली, और एक टाइट इंटीजर लूप पर जनरेट किया गया कोड 13 इंस्ट्रक्शन्स से घटकर 5 का हो गया — जो 4.9 गुना मापा गया। इस सेक्शन का हर दावा एक ही मशीन पर पहले और बाद में मापा गया था, अनुमान नहीं लगाया गया था।

प्रोजेक्ट किन चीज़ों को लेकर सावधान है

चार मेमोरी-करप्शन बग्स मिले और ठीक किए गए, जिनमें से हर एक अब एक परमानेंट टेस्ट द्वारा कवर किया गया है। कंपाइलर को 160 टेस्ट्स और बारह कोड-शेप गेट्स द्वारा चेक किया जाता है जो यह तय करते हैं कि किसी दिए गए कंस्ट्रक्ट को कितना कोड बनाने की अनुमति है। जहाँ प्रोजेक्ट किसी चीज़ को वेरिफाई नहीं कर सकता — Windows को अभी तक असली Windows मशीन पर रन नहीं किया गया है — यह साफ-साफ बता देता है, बजाय इसके कि कुछ और इशारा करे।
