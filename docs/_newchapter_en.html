18. What is new — the current language

This chapter was added after the rest of the book. Everything in it is part of the language today and has been verified against known answers, not just compiled once. If an earlier chapter does not mention something here, this chapter is the more current.

Floating-point numbers — dasham / दशम

A variable may hold a 64-bit IEEE-754 floating-point number. Declare it with dasham; a literal with a decimal point is a float automatically.

dasham x = 1.5
dasham y = 2.25
likha(x + y)      # 3.750000

Floats mix with integers (the integer is promoted), support all four arithmetic operators and all six comparisons, and print with six decimal places. Functions can return a float — the compiler infers that from what they return.

Growable arrays — kosh / कोश

An ordinary array (pankti) is fixed in size. A kosh grows: it starts at a small capacity and doubles as needed.

kosh xs[4]              # capacity 4, length 0
kosh_push(xs, 10)
kosh_push(xs, 20)
likha(kosh_len(xs))    # 2
likha(xs[0])            # 10
dasham last = kosh_pop(xs)

Capacity is not length. kosh xs[4] has capacity 4 but length 0, so xs[0] is out of bounds until something is pushed. This trips people up once; it is deliberate, and it is what makes indexing safe.

Typed arrays — kosh dasham

A kosh can be declared to hold floats. Integer values pushed into it are promoted, and its elements behave as floats everywhere.

kosh dasham temps[4]
kosh_push(temps, 36.6)
kosh_push(temps, 37)      # promoted to 37.0
likha(temps[1])            # 37.000000

Typed function parameters

A function can require a particular kind of argument, and the compiler checks it.

prakriya mean(kosh dasham xs) {
    dasham s = 0.0
    vitti i = 0
    yavat (i < kosh_len(xs)) {
        s = s + xs[i]
        i = i + 1
    }
    pratiyati s / kosh_len(xs)
}

A kosh dasham is passed as a pointer, so indexed writes are visible to the caller — a function can fill an array for you. But growing it is not allowed: calling kosh_push on a parameter is refused with a named error, because the pointer is passed by value and the caller would be left holding a stale one. This is a deliberate safety boundary, not a missing feature.

The Sutram IDE

Installed with the language. A single native program — no Python, no interpreter — with:

  • a code editor with line numbers and syntax highlighting;
  • Ctrl-R to compile and run what you have written, with the output shown below;
  • Ctrl-E to browse the example programs one at a time;
  • Ctrl-T for an interactive shell — type a statement, press Enter, see it run. The session remembers earlier lines, so you can build something up a step at a time;
  • Ctrl-S save, Ctrl-L load, Ctrl-Q quit.

On Windows the IDE is not yet available; use the interactive shell (sutram -i) instead.

Speed, measured rather than claimed

The compiler keeps variable values in processor registers instead of memory. On a representative numerical program this produced a measured speed-up of about 1.2× across recent rounds, and on a tight integer loop the generated code went from 13 instructions to 5 — a measured 4.9×. Every claim in this section was measured on the same machine before and after, not estimated.

What the project is careful about

Four memory-corruption bugs were found and fixed, each now covered by a permanent test. The compiler is checked by 160 tests and by twelve code-shape gates that assert how much code a given construct is allowed to produce. Where the project cannot verify something — Windows has not yet been run on a real Windows machine — it says so plainly rather than implying otherwise.
