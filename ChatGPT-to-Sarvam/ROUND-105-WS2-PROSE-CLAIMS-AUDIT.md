- **SUPPORTED BY TREE:** exact claim supported by available source, dated evidence, or a clearly labeled design/history passage. It does **not** mean ChatGPT reran its tests.

- **CANNOT CHECK FROM HERE:** evidence for a historical measurement, human linguistic review, GUI display, performance or example run is insufficient for independent certification. Use **NOT RUN - no toolchain** for every fresh execution gate.

## B. Claims that SHOULD remain (with proper version scope)

- `README.md:5–23` and `PROJECT-OVERVIEW.md:11–15`: Sanskrit keyword core and native pure-NASM direct executable generation are **SUPPORTED BY SOURCE** for ordinary compiled programs. “No runtime” means **no language/CRT dependency for ordinary programs**; it does not mean no operating system syscalls, and opt-in FFI is separate. Do not erase that architectural fundamental.
- `PROJECT-MASTER.md:288–306`: **“Sutram does not claim memory safety”**, **“No OS capability”** and the critique of mutant/proof coverage are appropriately qualified. The master explicitly distinguishes real Windows test from Windows **release**, which is good.
- `docs/sutram-design-parameters.html`: the prominent “requirements, not present behavior” warning legitimately scopes aspirational **“memory safety by default”**, generics, ownership and freestanding boot. **DO NOT** flag those dreams as false achievements; fix the **Today:** cells instead.
- `docs/sutram-benchmark-report.html`: it acknowledges several third-party numbers are estimates and that optimized C beats Sutram on a particular loop; preserve those caveats. `ROUND-97-WS3-BENCHMARK-ACCEPTANCE.md` defines a later **future** seven-workload target; that target was NOT RUN here.
- `docs/sutram-stdlib.html`: generated API text reflects library comments in many passages, but full generation currency cannot be certified from reading alone; **CANNOT CHECK FROM HERE** without rerunning the generator on an exact commit.
