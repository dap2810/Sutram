# Sutram ROUND-99 WS2 — Is the FFI test net strong enough?

**Answer: strong for *stage 1*, not strong enough for ABI expansion or malicious ELF input.** This is an independent **read-only** audit of actual `tests/r32/test_ffi.py` (Git blob `8cdbc315ae6e7d51917f83bc416b140f1dd3e28e`), `tests/r32/foreign.c` (`446e0acf0918dd09ff6797a6345f6925a1581509`), `main.sm` (`527e89e19d4bd995d67edbcc48d8a5b03d8622a6`), `ffi.sffi` (`6780f3452aef0da5a6f25304a75a5e0d6b5e9eda`), and `linker/sutram_elf2smo.asm` (`591011aaaad62d7b42ad1cb820df992499e686d6`). Prior Claude R32 reported **44/44 native FFI checks PASS**, 27 Linux gates PASS/0 FAIL/1 Windows NOT_RUN; **ChatGPT R99 did not rerun native Sutram tests** (NASM unavailable here).

## What is already covered — retain it

The assertion that R32 tests *only one two-argument function* is **false**. The successful program calls **four C functions** taking **0, 1, 2 and 6 integer arguments**, including positive/negative integers, from `mukhya` and a separately built module, with recursion and a foreign `rsp mod 16` control at multiple depths (`tests/r32/test_ffi.py:70–88`). The **actual C file** defines `sutram_ffi_add`, `sutram_ffi_neg`, `sutram_ffi_mix` and `sutram_ffi_rsp`. Valid output is pinned as exact stdout and exit. Wrong **1** and **3** arguments to a 2-arg declaration are tested under **both `--object` and `--separate`** with `E_ARITY` and absent `.smo` (`test_ffi.py:90–101`). A foreign declaration exports no local `FUNCDEF` and the relocation uses the **foreign** symbol; collisions with user/builtin names are refused. The test covers about **21 malformed sidecar scenarios** (wrong header, missing/extra fields, bad arity/kinds/names, duplicates, large file), Hindi diagnostic, ELF relocation/unwind/truncation/non-ELF/usage refusals, one undeclared symbol link error, cache invalidation when the **sidecar** changes, and the unchanged default compiler route (`test_ffi.py:103–198`). **These are valuable regression controls.**

| POSIX stage-1 `i64 → i64` | **COVERED** | No `dasham/f64`, pointer/string, `void`, structs, or actual Windows FFI |

These are **test-scope observations**, not claims that the existing compiler fails those untested cases. Type mismatch is a special design danger: a sidecar can claim `i64` while a C function with the *same symbol* actually expects `double`; `STT_FUNC` carries no argument types, so neither the existing named linker nor the converter can validate that cross-language promise. **Do not advertise typed ABI verification of arbitrary C objects** without a trusted C-side signature/header or a separately reviewed ABI compatibility contract.

## Minimum regression suite additions, in priority order

1. **P0 — Malformed ELF fail-closed and output absence:** modify a copy of known-good `foreign.o` *by bytes* to test invalid ELF class/data/version/machine, `e_shoff` near `UINT64_MAX`, too-large `e_shnum`, truncated `sh_link` string table, non-NUL-terminated symbol name, invalid `st_shndx`, overlarge `st_value+st_size`, duplicate/global/weak symbol, extra allocated rodata/BSS, and nonempty `REL/RELA`. Run the NASM converter as a child with timeout; require **controlled nonzero exit, no crash/hang, no output `.smo`**, stable diagnostic. Do not regenerate or overwrite accepted corpus files; add isolated mutations to a separate R99 test. The current `test_ffi.py` checks rejection messages but often **does not assert no output was published** on converter/sidecar failures.
2. **P0 — Cross-language signature honesty:** confirm a sidecar with correct arity but mismatched **C prototype** is NOT considered verified merely because it links. Add a build contract where expected `i64` types are checked against an explicit trusted C-interface declaration/metadata (or mark unsafe and require user responsibility). **Do not execute intentionally mismatched calls as a security test**: classify their ABI violation statically in test metadata.
3. **P0 — Exact native sidecar boundary tests:** 0-arity call with 1 arg; 6-arity with 5/7; valid 3/4/5 positive calls; nested foreign calls as arguments and multiple calls per expression; near 8192-byte/64-record limits with one-byte-over cases; invalid UTF-8, NUL and duplicate foreign binding; missing sidecar; ensure **no `.smo` on error** every time and output file isn't replaced/truncated on failure.
4. **P1 — Pointer, `void` and `f64` only *when actually implemented*:** for pointer: a valid caller-owned buffer and length, read-only C sum and out-of-bounds negative caught at Sutram boundary, no dangling pointers; for `void`: statement call succeeds, using result in expression is a compile error; for `f64`: `double add(double,double)`, a mixed `i64,f64,i64,f64` call, `xmm0` return and bitwise output including NaN/-0. Before implementation, the **existing v1 parser must continue rejecting these kinds**, with no output artifacts.
5. **P1 — Linking, reuse and symbol ownership:** two separate freestanding C `.o` objects, one Sutram root+one imported module, duplicated foreign symbol (reject), missing declared C symbol (reject + **no executable**), `.o` changed under warm `--cache`, non-root callback via separate mode and correct module ownership. Assert final output hash and exit, not only builder logs. Resolve collisions involving a sidecar external symbol and a user-defined function across units.
6. **P1/P2 — Localization/platform acceptance:** all supported Sanskrit/Hindi/Gujarati diagnostic packs exercised in accepted and refused foreign calls; Wine explicitly reported as Wine, plus **actual native Windows x64** after a PE/COFF FFI is implemented and owner's baseline is recorded.

## Required evidence before saying "FFI regression net is strong"

- On **this exact commit** record source and prebuilt `.o` SHA-256/ELF section+symbol metadata (tests use a committed `foreign.o`; the FFI test does not compile its C source each run). Rebuild from C in a **separate developer control** and compare structural ABI/expected outputs, allowing toolchain-specific bytes.
- Run canonical Linux `gates.sh`, `tests/r32/test_ffi.py`, separate/module linker gates, fuzz/crash corpus; **R32 fuzzers currently do not generate FFI programs**. Add bounded *FFI-aware* valid-call + malformed-sidecar/object fuzz, exercising compiler, converter and project NASM linker rather than only a Python oracle.
- For each negative, assert **nonzero status, stable class of error, no object/executable, no hang or signal**, check the check, and ensure old ordinary mode remains byte-identical. Stage-2 kinds cannot be marked feature PASS until their explicit negative and native positive tests exist.

**Priority call:** harden the native converter's malformed-input and fail-closed tests **before** broadening foreign data/relocations or claiming any new ABI type. An untrusted `.o` is executable machine code; ELF metadata validation does not make it sandboxed. **R99 only audited the net and ran separate GCC host ABI controls (8/8); it did not run `tests/r32/test_ffi.py` or edit the compiler/tests.**
