## Additional FFI limits to retain in roadmap

- **More than six args:** Sidecar limits `arity=0..6`. First four Windows parameters by position in `RCX,RDX,R8,R9` or XMM0–3; 5/6 already tested on stack, **7+ intentionally rejected**. No general stack argument scalability yet.
- **C variadics and libc `printf`:** require MS vararg floating duplication/ABI details, genuine CRT link strategy and a separately approved runtime-dependency decision. Under current no-CRT design these remain UNSUPPORTED, not accidental feature coverage.
- **C→Sutram callbacks:** inverse calling convention, nonvolatile GP and XMM6–15 preservation, lifetime of callback pointers, stack/shadow rules, typed error propagation and register status; not implemented. Window-side `w_clobber` exercises destruction of *volatile* registers but is **not proof** that arbitrary reverse callbacks preserve all nonvolatile registers.
- **Static type proof across C/COFF/Sutram:** COFF exported symbols do not carry C arity, `const`, struct layout or return type. The sidecar declares a contract the programmer must honor. A mismatched C prototype with the same decorated/undecorated linker symbol may produce silent wrong answers; require trusted C header/ABI manifest generation or an explicit `unsafe` boundary before claiming typed safety.
- **Artifact/runtime interoperability:** foreign code with read-only data alignment up to 16 accepted; outside this bounded subset (writable globals, external symbols, data relocation, exception tables) refused. Re-run COFF mutation and no-output-on-failure tests at exact promoted merge; reported 100,000 malformed objects on Linux build and 3,000 on Windows build are prior evidence.
- **Windows localization:** Windows `SUTRAM_LANG` environment is not read by the compiler, so a target-language override via that variable does not work there (per Windows owner handoff). Separate from the FFI ABI but impacts acceptance of the eleven language packs.
