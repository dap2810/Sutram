## Gate implementation contract (without writing a new tool in this round)

A proper partner-owned `tools/doc_contract_gate.py` or equivalent could emit these **machine-readable statuses per excerpt**:

`STATIC_PASS` — documented symbol/command exists at pinned source and its snippet classification is decided; **NOT** behavioral success.
`STATIC_FAIL` — documented module/function/CLI no longer exists or signature mismatches.
`REVIEW_REQUIRED` — a missing precondition, dynamic pointer extent, potentially destructive command, ambiguity, historical sample without status, or unclassified fragment.
`NATIVE_PASS` — exact pinned deterministic positive/negative fixture genuinely compiled/executed and matched its recorded contract.
`NATIVE_FAIL` — mismatch/crash/unexpected output or diagnostic.
`NOT RUN - no toolchain` — execution prerequisites absent (not a pass).

**No line can be green solely because an API is in an allowlist**; enumerate the entire currently published surface and catch new/removed names. Maintain exact source/generator/output SHA and expected fixture manifest. Keep normal/FFI/Windows modes separate. If a generator regenerates a page from old comments, a **byte-match alone can be perfectly reproducible and still wrong**. This is the fifth-class counterpart to the earlier allocation-source spelling/provenance problem.
