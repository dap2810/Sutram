A · Compiler core — 88%

20,230 lines of hand-written x86-64 assembly in one file; emits native ELF, links PE32+.

  • ✔ Lexer, parser, AST, codegen, ELF writer, 32 keywords, 10 language packs
  • ✔ Arrays, kosh growable arrays, structs, enums, switch, floats, byte strings
  • ✔ 186 regression tests + 12 codegen ceilings held through every change
  • ✗ PE end-to-end: a Windows binary that actually runs (blocked on a Windows machine)
  • ✗ Namespaced modules / real import semantics beyond inlining
  • ✗ `char_code`/arity guards extended to the last few legacy builtins

B · Optimiser — 15% biggest single gap

Measured: 5.4× slower than hand-optimal code on s = s + i*2. Cause is known.

  • ✔ Locals in registers; bottom-tested loops; one-instruction literal loads; call register-saves removed
  • ✗ Register-based expression evaluator — stop pushing/popping operands that are already in registers (largest win)
  • ✗ Loop-invariant code motion (hoist i*2 out of the loop)
  • ✗ Constant folding and propagation
  • ✗ Peephole pass; strength reduction (*2 → add)
  • ✗ Dead-code elimination; a repeatable A/B benchmark harness as the gate

C · Language surface — 60%

  • ✔ Functions, parameters, returns, recursion, forward prototypes (mutual recursion works)
  • ✔ Module-level globals — done and verified as R56: shared storage, local shadowing, ordered once-only initialisers, PE .data
  • ✗ Generics / templates (one array type, not many)
  • ✗ First-class functions, closures, lambdas
  • ✗ Error values / exceptions / result types
  • ✗ Pattern matching, destructuring
  • ✗ Declared scalar types, unions, type aliases

D · Standard library — 50%

19 modules, 186 functions, 153 proofs, 39 properties. Strong in data structures and maths; thin in everyday text and I/O.

  • ✔ map, set, strb (byte strings), string, sort, bigint, hash, math, sankhyiki (stats), baseconv, strconv, array, util, heritage modules
  • ✔ Sets — lib/set.smlib, done and verified as R14: union, intersect, difference, subset, sorted to_array
  • ✗ Lists / queues / stacks built on kosh
  • ✗ Formatting and templates (printf-style, or interpolation)
  • ✗ File I/O breadth (read whole file, line iteration, directories)
  • ✗ Time and dates
  • ✗ JSON / CSV / simple serialisation
  • ✗ Regex or even glob matching
  • ✗ A documented stability promise per module

E · Diagnostics & errors — 60%

4 · Critical path — what to do in what order

Ordered by what unblocks the most, not by what is easiest.

#Next stepWhy it is hereEffort
1Register-based expression evaluator Closes most of the measured 5.4× arithmetic gap. Contained, measurable, and the compiler is otherwise feature-complete enough to stop hiding behind missing features.large
2Module-level globals (in flight) Removes the state-threading that makes every non-trivial program awkward. Already designed.medium
3One verified Windows run Turns the project’s biggest unverified claim into a fact. Needs a Windows machine, not code.small*
4Optimiser, part 2: LICM, constant folding, peephole Only worth starting once the expression evaluator is register-based — otherwise it optimises a stack machine.large
5Library breadth: formatting, file I/O, lists, time The 45% bar is the one most within reach, and it is what a user feels first.medium
6IDE: file picker, replace (clipboard done in slice 16) Cheap, visible, and makes the IDE usable for real editing rather than demos.small
7Debugger The biggest remaining tooling gap; needs the diagnostics work to be finished first.large
8Versioned releases + package manager Makes the project distributable rather than a zip collection.medium
9Concurrency Last, deliberately. Expensive and furthest from the core goal.very large

* small in code, but it requires a Windows machine and a least-privilege account — that is the real blocker, and it has been open for many rounds.

5 · The shape of what is left

Already done and verified

  • ✔ A real native compiler that beats Node by 8× and Python by 167× on a loop
  • ✔ 186-test safety net + four byte-identical reference binaries held across every merge
  • ✔ Real diagnostics: located, recoverable, accumulating, correct provenance
  • ✔ 18-module library with proofs and properties
  • ✔ A 15-feature IDE, all slices verified
  • ✔ Books and docs in six languages

Still ahead

  • ✗ No optimiser — the clearest, biggest gap
  • ✗ Windows has never run a generated binary
  • ✗ No concurrency, no FFI, no package manager, no debugger
  • ✗ Library thin on everyday text, files and time
  • ✗ Language lacks generics, closures and error values
  • ✗ One user and two AI agents — no community yet
