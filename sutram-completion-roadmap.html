A · Compiler core — 88%

20,230 lines of hand-written x86-64 assembly in one patra; emits native ELF, links PE32+.

  • ✔ Lexer, parser, AST, codegen, ELF writer, 32 keywords, 11 language packs
  • ✔ Arrays, kosh growable arrays, structs, enums, switch, floats, byte strings
  • ✔ 186 regression tests + 12 codegen ceilings held through every change
  • ✗ PE end-to-end: a Windows binary that actually runs (blocked on a Windows machine)
  • ✗ Namespaced modules / real import semantics beyond inlining
  • ✗ `aksharank`/arity guards extended to the last few legacy builtins

B · Optimiser — 15% biggest single gap

Measured: 5.4× slower than hand-optimal code on s = s + i*2. Cause is known.

  • ✔ Locals in registers; bottom-tested loops; one-instruction literal loads; call register-saves removed
  • ✗ Register-based expression evaluator — stop pushing/popping operands that are already in registers (largest win)
  • ✗ Loop-invariant code motion (hoist i*2 out of the loop)
  • ✗ Constant folding and propagation
  • ✗ Peephole pass; strength reduction (*2 → add)
  • ✗ Dead-code elimination; a repeatable A/B benchmark harness as the gate

C · Language surface — 60%

  • ✔ Functions, parameters, returns, recursion, forward prototypes (mutual recursion works)
  • ✔ Module-level globals — done and verified as R56: shared storage, local shadowing, ordered once-only initialisers, PE .data
  • ✗ Generics / templates (one mala type, not many)
  • ✗ First-class functions, closures, lambdas
  • ✗ Error values / exceptions / phal types
  • ✗ Pattern matching, destructuring
  • ✗ Declared scalar types, unions, type aliases

D · Standard library — 50%

19 modules, 186 functions, 153 proofs, 39 properties. Strong in data structures and maths; thin in everyday text and I/O.

  • ✔ nighantu, sangrah, khand (byte strings), varna, shreni, brihat, gudh, ganit, sankhyiki (stats), aadhar, vakyank, mala, sadhan, heritage modules
  • ✔ Sets — lib/sangrah.smlib, done and verified as R14: union, intersect, difference, subset, sorted to_array
  • ✗ Lists / queues / stacks built on kosh
  • ✗ Formatting and templates (printf-style, or interpolation)
  • ✗ File I/O breadth (read whole patra, line iteration, directories)
  • ✗ Time and dates
  • ✗ JSON / CSV / simple serialisation
  • ✗ Regex or even glob matching
  • ✗ A documented stability promise per module

E · Diagnostics & errors — 60%

  • ✔ --check mode: located patra:line:column, source line + caret, bounded recovery
  • ✔ Multiple errors accumulated in one run; correct patra attribution through nested and namespaced imports
  • ✗ Every remaining diagnostic family carries a location
  • ✗ Windows --check verified
  • ✗ Warnings (unused variable, unreachable code, shadowing)
  • ✗ “Did you mean …?” suggestions for misspelled keywords and names
  • ✗ A stable, documented error-code catalogue

F · IDE & developer tooling — 58%

Linux X11 IDE, 2,523 lines, 17 working slices, all verified against a mock server.

  • ✔ Edit, compile-and-run, save/load, 8-level undo, four arrows, Home/End, Tab, Ctrl-Home/End, find, both panes scrolling
  • ✔ Clipboard — selection model (Shift+arrows/Home/End), Ctrl-A / Ctrl-C / Ctrl-X / Ctrl-V, whole-line copy and cut, selection highlight, Escape clears before quitting
  • ✔ Slice 16 verified: 8 clipboard checks read the buffer back through the real Ctrl-S save path, with a negative control against the slice-15 binary
  • ✔ Open / new — Ctrl-O opens any patra by path, Ctrl-N starts a new buffer (slice 17)
  • ✔ Fixed a pre-existing defect: the editor repaint overpainted the prompt strip, so the find prompt had never actually been visible
  • ✔ Open any patra by path (Ctrl-O) and new buffer (Ctrl-N) — slice 17; a graphical directory browser is still to come
  • ✗ Find-and-replace
  • ✗ Syntax highlighting and bracket matching
  • ✗ Debugger (breakpoints, step, inspect) — the biggest tooling gap
  • ✗ Formatter / auto-indent
  • ✗ Windows IDE (Linux-only today)

G · Cross-platform & packaging — 38%

  • ✔ One source → Linux ELF and Windows PE32+; Linux installer script; Windows .exe; portable zips
  • ✔ Both Windows binaries now build and verify — sutram.exe (PE32+ console) and sutram-ide-gui.exe (PE32+ GUI), headers inspected, import tables present
  • ✗ Verified Windows run — the largest unverified claim in the project
  • ✗ Windows CI in the pipeline
  • ✗ Versioned releases (semver, tags, changelog per release)
  • ✗ Package manager / dependency mechanism
  • ✗ Reproducible-build check (same source → same bytes, pinned toolchain)
  • ✗ macOS, or a documented “not planned”

H · Verification & QA — 85%

  • ✔ 186 + 3 tests, 12 codegen ceilings, 30 pack checks, 18 module-graph tests
  • ✔ 147 library proofs, 33 properties, R46 parity 4/4 held across every merge
  • ✔ Seven independent acceptance harnesses (R48–R55), each re-run on merge
  • ✗ Fuzzing / random-program generation
  • ✗ Coverage measurement (which compiler paths are never exercised)
  • ✗ A documented, minimal test corpus for each language feature

I · Docs & teaching — 70%

  • ✔ Language reference, 29 doc pages, books in English/Hindi/Sanskrit/Tamil/Telugu/Gujarati, generated stdlib reference
  • ✗ A step-by-step tutorial (“write your first Sutram program”)
  • ✗ Per-module API docs with examples
  • ✗ Books refreshed to the shipped version (they lag the compiler)
  • ✗ Migration notes for every breaking change

J · Concurrency — 0%

  • ✗ Everything. No threads, no async, no atomics, no green threads.
  • Honest position: this is the most expensive remaining item and the least connected to the project’s core goal.

K · Ecosystem & community — 5%

  • ✗ Package manager and a place to publish modules
  • ✗ Third-party libraries
  • ✗ Outside contributors, issue tracker process, release governance
  • Cannot be engineered. Needs people first.

4 · Critical path — what to do in what order

Ordered by what unblocks the most, not by what is easiest.

#Next stepWhy it is hereEffort

2Resolve the Gujarati pack collisionR66 is merged except one patra; the pack reserves a word an accepted test uses as a variable.small
3Finish the Indic roll-outSanskrit and Gujarati carry the device sangrah; the rest are mechanical from that template.medium
4Register-based expression evaluatorCloses most of the measured arithmetic gap.large

5 · The shape of what is left

Already done and verified

  • ✔ A real native compiler that beats Node by 8× and Python by 167× on a loop
  • ✔ 186-test safety net + four byte-identical reference binaries held across every merge
  • ✔ Real diagnostics: located, recoverable, accumulating, correct provenance
  • ✔ 18-module library with proofs and properties
  • ✔ A 15-feature IDE, all slices verified
  • ✔ Books and docs in six languages

Still ahead

  • ✗ No optimiser — the clearest, biggest gap
  • ✗ Windows has never run a generated binary
  • ✗ No concurrency, no FFI, no package manager, no debugger
  • ✗ Library thin on everyday text, files and time
  • ✗ Language lacks generics, closures and error values
  • ✗ One user and two AI agents — no community yet
