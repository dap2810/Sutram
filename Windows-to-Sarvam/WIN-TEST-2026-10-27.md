1. **Devanagari from the command line needs `--lang sanskrit`.** Without it, `लिख` is not recognised

   Devanagari program's output is byte-identical to the Latin one. Is that intended?
2. **There are two Devanagari spellings of `prati`.** `lang/sanskrit.lang:18` and `docs/LANGUAGE-REFERENCE.md:326` give
   `प्रतियाति`; the compiler's built-in `kw_dev_pratiyati` holds the bytes for `प्रत्यायति`. Both compile with
   `--lang sanskrit`. Which one is canonical? (The test prompt's `प्रति` is defined by neither; that was a prompt error.)
3. **Every error starts with the English words `Sutram Error`, even with `--lang sanskrit`.** Some also have the
   English code `[E_UNDEFINED_NAME]`. The message bodies are Sanskrit in all four tests. Is the prefix deliberate, or
   does it break the "never English" rule?

## 3. Every failure, verbatim

### 3a. Devanagari program exactly as given in the prompt

`t_dev.sm` (UTF-8, no BOM, LF; the first bytes are `E0 A4 AE E0 A5 81 …`, which is `मुख्य`):

```
PS> .\sutram_win.exe t_dev.sm t_dev.exe
t_dev.sm:6:5: Sutram Error [E_UNDEFINED_NAME]: agyat naam 'प्रति'
      प्रति 0
      ^
Sanket: prayogat purvam ghoshana avashyaki: vitti प्रति = ...
DEV_COMPILE_EXIT=1
```

The second try, exactly as written, gave identical output, exit 1.

With the Sanskrit pack:
```
PS> .\sutram_win.exe --lang sanskrit t_dev.sm t_dev.exe
भाषा-पुटः प्राप्तः: sanskrit
t_dev.sm:6:5: Sutram Error [E_UNDEFINED_NAME]: अज्ञातं नाम 'प्रति'
      प्रति 0
      ^
सूचना: प्रयोगात् पूर्वं घोषणा आवश्यकी: वित्ति प्रति = ...
AS_WRITTEN_LANG_SANSKRIT_EXIT=1
```

I checked the tree for the Devanagari spelling of `prati`:
- `lang/sanskrit.lang:18` and `docs/LANGUAGE-REFERENCE.md:326` give `प्रतियाति`.
- The compiler's built-in table (`src/sutram_compiler.asm`, `kw_dev_pratiyati`) holds the bytes for `प्रत्यायति`.
- Plain `प्रति` is not a keyword anywhere. The prompt's program uses a spelling the language does not define.

Without the flag, only some Devanagari keywords are built in (`मुख्य`, `वित्ति`, `प्रत्यायति` …), and `लिख` is not one of them.

## 5. Anything surprising

1. **Every error message starts with the English words `Sutram Error`.** The message bodies are Sanskrit
   (`agyat prakriya`, `mala ank seema atikram`, `riktat koshat kosh_pop`, `nivesh patra aprapt`). The prefix stays English
   even with `--lang sanskrit`. Example: `Sutram Error: निवेश-पत्रम् अप्राप्तम्`. The `E_UNDEFINED_NAME` diagnostic also has an
   English code: `Sutram Error [E_UNDEFINED_NAME]`. The `lang/*.sandesh` files keep the `Sutram Error:` prefix too, so the
   prefix may be deliberate. Against the prompt's rule ("never English"), it is English text in every error.
2. **The version is v254, not v253.** The prompt says `main` is at compiler v253. The tree at `2ec4c18f` reports
   `Sutram 1.0 (v254)` (`src/sutram_compiler.asm:237`), and the committed `sutram.exe` and `win\sutram.exe` say the same.
3. **The IDE is not at `win\sutram-ide-gui.exe`.** `Test-Path .\win\sutram-ide-gui.exe` → `False`. It is in the repo root,
   next to `sutram.exe`, `lang\`, `lib\` and `examples\`, and I launched it from there. `win\` holds a `sutram.exe` but
   no `lang\`, `lib\` or `examples\`.
4. **Errors go to stdout, not stderr.** This applies both to compile errors (4a, when redirected: stdout has the message,
   stderr is empty) and to runtime traps (4b, 4c).
5. **`likha(<integer>)` adds a newline.** `likha(x + y)` then `likha("\n")` prints `15\n\n`, not `15\n`. The Devanagari and
   Latin versions agree on this.
6. **The Windows build is not byte-identical to the committed `sutram.exe`:** 413,825 bytes built here vs 413,180 committed.
   The build used the first `ld` on PATH, MSYS2 ld 2.47, as the prompt's command does. The prompt's `ld` line also has no
   `--subsystem console --no-insert-timestamp`. The behaviour tested here was correct, and `--version` matches.
7. With `--lang sanskrit`, a runtime-trap program is larger (4b: 352 bytes vs 284) because the Devanagari message is
   embedded in the binary. This is expected, but worth knowing.
8. `nasm` took 4.7 s. The produced compiler compiles a program in ~0.004 s warm.
9. No tracked file was modified (checked with `git status` / `git diff`). The IDE run created no file in the tree.
