An output match does not establish the child exit code: this driver reads the output pane, not the child process exit. In particular, the Linux inline-syscall example `29_nishkriya` matches displayed text but the earlier native run returned 0 instead of expected 42. Compiler-rejection prefix matches are checked separately; the original driver only searched for a diagnostic keyword. Files without goldens are observations, not passes. Nested language examples use Auto detection in this sweep; failures need an explicit-pack follow-up before being assigned to the compiler. No golden or compiler source was changed.

The eight nested native-script cases were rerun with explicit language selection. All eight then matched their beside-source expected output. The follow-up also reran the other eight nested cases; raw output and screenshots are in `ide-v297-2026-11-03/explicit-packs/`.

The comparison accounts for expected stderr merged into the IDE output pane and the IDE’s abnormal-termination note for expected nonzero exits. Module diagnostics normalize path separators and the `<ROOT>/` prefix. These display differences are not counted as compiler defects.
