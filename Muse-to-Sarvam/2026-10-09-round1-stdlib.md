## 1. The library: array / io / net

**`array` — IMPLEMENTED.** The sketch described real abstractions over raw
memory (`nirmmita`/`likh8`/`pad8`), so I wrote them as actual functions:
`array_new`, `array_set`, `array_get`, `array_fill`, `array_copy`,
`array_sum`, `array_set_safe`, `array_get_safe` (8 functions). Verified by
execution: fill 5×10, set index 2 to 99, sum = 139; safe variants return 0
on out-of-bounds.

**`io` — DELETED.** Every "function" was a one-line rename of a builtin
(`io_print` → `likha`, `io_read` → `paadh`, …). A module that only renames
builtins adds indirection without abstraction. The builtins are the API.

**`net` — DELETED.** Same reason (`net_socket` → `netsock`, …). The only
consumer was comments; no `.sm` file called `net_*`.

`examples/import_demo.sm` used `ayojan io`; removed that line (it never called
`io_*`, only builtins). Rebuilt and ran — output unchanged.

**Gap fills (quality over count):** `str_equals(a, b)` in string.smlib,
`bit_count(n)` in math.smlib. Both verified by execution.

Library is now 13 modules, 113 functions (was 12 + 3 sketches, 103).

## 2. The proof harness — `tools/proof_lib.py`

- Discovers `tests/stdlib/*.sm`, compiles each with a freshly built compiler
  (builds via NASM if `build/sutram_compiler` is missing or stale), runs the
  binary, compares stdout and exit code against golden `.out` / `.exit`.
- `--record` regenerates goldens from actual runs. Default mode checks.
- Failure output names the test, then the specific mismatch with expected
  vs actual values quoted. No silent passes.
- Runs from a clean checkout with no arguments: verified by deleting
  `build/` and running `python3 tools/proof_lib.py` → builds compiler,
  **113 passed, 0 failed**.

## 3. Per-function tests — `tests/stdlib/`

113 test programs (one per function), each `ayojan`s its module, calls the
function with 2–4 representative inputs including edge cases, prints via
`likha`. Goldens recorded from actual runs via `--record`, then **every
golden hand-verified** against independently computed values before
accepting. Examples of verified values: gcd(12,8)=4, fib(10)=55,
is_prime(17)=1, collatz_steps(6)=8, madhava_pi()=3.141593,
mat_gunana([1,2;3,4]×[5,6;7,8])=[19,22;43,50], find_char("hello",108)=2.

Two investigations during verification (both resolved as correct behavior,
not bugs):
- `kuttaka(10,6,4)` → 4, not 1: 10·4=40≡4 (mod 6); the docstring promises
  "a particular solution" and 4 is valid (differs from 1 by b/gcd=3).
- `madhava_atan(1.0)` → 0.784773 vs π/4=0.785398: the 400-term Gregory
  series' known slow convergence at x=1, not a defect.

No library bugs found. Nothing was blindly recorded.
