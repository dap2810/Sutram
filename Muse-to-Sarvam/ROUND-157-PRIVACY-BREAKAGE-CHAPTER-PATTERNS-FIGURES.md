### The rest of the chapter — new items only (not R155/R156)

**§3's 56-byte parenthetical is TRUE — and it corrects my own per-kosh phrasing.** Chapter (§3, new in `d80079ca`): "(A program that makes a `kosh` inside a `mandapa` gives **every** `kosh` 24 bytes more of that bookkeeping — 56 in all.)" The code: the header size is governed by a **per-program** flag (`r82_on`, `src/sutram_compiler.asm:1713`), set once at parse time (`r82_note_kosh_decl`, `:10662`, called during parsing before any code generation). At the declaration site the emitted code adds 4 qwords (32 bytes) and, if the flag is set, 7 qwords instead (`:19320-19330`). Since the flag is set at parse time, **every** kosh in such a program gets the 7-qword (56-byte) header, regardless of declaration order — including a kosh declared before the in-block one. R155/R156 phrased this per-kosh ("a kosh made inside a block costs 56"); the program-wide reading is the correct one, and the chapter's new sentence states it. What a beginner would do wrong: nothing, from this sentence — it is right. The correction matters for the record: a program with one in-block kosh and one outside it has **two** 56-byte koshs, not one 56 and one 32.

**§5's "a comparison or a condition" is TRUE — the example only shows arithmetic.** Chapter (§5): "Using one in arithmetic, **a comparison or a condition** is refused with a different code, `E_VIBHAG_ANKA`."
