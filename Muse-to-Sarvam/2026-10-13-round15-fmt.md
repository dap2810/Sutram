## What was built

`lib/fmt.smlib` — 23 functions. **Representation: BYTE strings** (packed bytes, explicit lengths, `strb` idiom). This is a deliberate contrast with `lib/strconv.smlib`, which works on CELL arrays (pankti of char codes) and has no width/alignment/grouping/fixed-decimal/sign surface. fmt outputs are bytes (read with `char_at`); strconv outputs are cells (read with `[i]`). Do not mix them.

| Family | Functions |
|---|---|
| Integer bases | `fmt_int_base(v, base, out)`, `fmt_int_flags(v, base, flags, out)`, `fmt_dec`, `fmt_hex`, `fmt_hex_upper`, `fmt_oct`, `fmt_bin`, `fmt_int_pre(v, base, upper, out)` |
| Padding / alignment | `fmt_pad_left`, `fmt_pad_right`, `fmt_pad_center` (all `(src, sn, width, padbyte, out)`) |
| Grouping | `fmt_group` (default), `fmt_group_indian`, `fmt_group_intl`, `fmt_group_int(v, indian, out)` |
| Fixed decimals | `fmt_fixed(dasham x, places, out)`, `fmt_fixed_signed(dasham x, places, out)` |
| Signed | `fmt_signed(v, out)`, `fmt_sign_char(v, signch, out)` |
| Internal helpers | `fmt_digits`, `fmt_digits_base`, `fmt_group_impl`, `fmt_fixed_impl` (listed in docs; marked internal in comments) |

**Defaults, stated in code and header:**
- Bases: no prefix unless the `_pre` / flags form is used. Flags: bit 0 (1) = prefix (`0b`/`0o`/`0x` for 2/8/16, none for other bases incl. 10); bit 1 (2) = uppercase digits. The prefix itself stays lowercase even with uppercase digits.
- Grouping default (`fmt_group`): **Indian** (`12,34,567`), because the audience is Indian.
- Rounding (`fmt_fixed`): **half away from zero** (`2.5 -> 3`, `-2.5 -> -3`).
- Centre padding: the extra pad byte goes **right**.
- `fmt_fixed` places clamped to 0..9; places 0 emits no `.`.
- `fmt_group_*` keep a leading `-`/`+` and copy a `.fraction` verbatim.
- **INT64_MIN excluded** from the integer formatters (negating it overflows, same as strconv). Every other int64 value works.
- `fmt_fixed` exact while `|x| * 10^places < 2^52`; `|x| * 10^places` must fit in int64.

## Bugs and traps found during this round (all fixed before any golden was recorded)

1. **Grouping remainder bug (real bug in `fmt`).** The first version grouped left-to-right with fixed group sizes, so `1234567` (Indian) came out `12,34,56,7` — the remainder landed in the *last* group instead of the first. Rewritten with remainder-based boundaries: a comma goes after digit `i` iff the digits remaining after it mark a boundary (intl: `rem % 3 == 0`; Indian: `rem == 3`, or `rem > 3` with `(rem-3) % 2 == 0`). Caught by a smoke program.
2. **Untyped parameters truncate floats (language trap).** `fmt_fixed(3.14159, ...)` first arrived as `3.0`: an untyped parameter receives the integer part of a `dasham` argument. The fix is a typed parameter — `prakriya fmt_fixed(dasham x, places, out)` (as in `sankhyiki_sqrt`) — which receives the full float, mixed with untyped params. `fmt_fixed`, `fmt_fixed_signed`, `fmt_fixed_impl` all use it. A `dasham` value assigned to a `vitti` local still truncates toward zero (verified: `3.7 -> 3`, `-3.7 -> -3`), which is what the rounding step relies on.
3. **Redeclaration is silently ignored (language trap).** `vitti x = 1` followed later in the same scope by `vitti x = 2` leaves `x == 1` — the second initializer is dropped, no error. This bit the `fmt_group_digits` property generator (reused `gn0` for indian then intl). All property generators now use unique indexed names per assignment. Callers should treat redeclaration as an error-in-waiting, not a feature.
4. **`pad` is a reserved builtin name (R54).** A local `vitti pad` fails to parse. Renamed to `npad` in the three pad functions.
5. **My own process slip, caught by counting.** When appending the five fmt properties, I dropped the existing last list entry (`set subset`), so the run showed 43/43 instead of the expected 44. Restored; the run now shows 44/44. The lesson is the same as the R14 one: count the list, don't trust the edit.
