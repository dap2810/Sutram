## WS3 — what I did NOT rename, and why

- **`len` in `lib/` (30 local variables).** The meaning is in the prefix (`slen`, `keylen`, `seglen`).
  `saayam`/`keyaayam` would read worse. **The public length function is already `vartani_aayam`.**
- **`kosh_len`** is a builtin. It belongs to the 21 builtin names with an English part (R44's list), which is a
  separate decision for the owner.
- **`intpart`** is a local variable inside a function body. A user never sees it.
- **"char-code array"** is prose describing a data layout, not a name. It is left for the documentation round.
- **`slice` → `vibhag` in the user-facing documents.**
  - `PATH-TO-COMPLETION.md` assigns prose to ChatGPT and Sarvam, not Claude, and it wins over a brief.
  - ChatGPT's R122 is the documentation-impact round.
  - **`vibhag` is already the keyword** (R23), so it is a pure prose change.
- **`sat_div` in `tools/proof_props.py`.** These are failure labels ("FAIL sat_div") that name a historical
  mutation target. They are not called and not user-visible. **Renaming a proof's label breaks the comparison with
  its own past transcripts.**
- **The internal assembler labels** (`bn_charat`, `bn_vartlen`, …). As v373 says, a user never sees them.

**Not touched:** `backups/`, `lang/` and `windows/`. **The non-Sanskrit packs are unchanged.**
